# 选取与改写保真

`schema_version` 仍是 `ideas-0.1`。本文件是 `SKILL.md`「选取与改写保真」的细则。字段和 AC10 以 `schema.md` 为准。这里不新增节点字段。

准确传递这句 Idea 要说的意思。好听、好排、好写成几步机制，都排在保真后面。

## 选取

| 情况 | `origin` | `expression` 怎么取 |
|---|---|---|
| 他亲口说完整的一句（周记、聊天或确认记录） | `jake` | 优先整句原话。不要先改写再确认 |
| 模型从多句归纳、补问、改写出来的 | `ai_extension` | 只能标 `candidate`。确认前不得当成他的观点，也不预填 `confirmed` |
| 短清单已标可公开，但还没有确认这句 `expression` | 按上一行的来源 | 可当作来源线索。不等于 content 能用的 `expression` |

离开原文也要能看懂：适用场景、限制写全。不为凑数硬拆，也不为了更像一篇文章而换因果。

能整句用原话就用原话，少动。模型做了任何改写，包括只动表面的那一种，`origin` 仍是 `ai_extension`，直到他确认这句。确认之后 `origin` 也不改成 `jake`。记录形状见 `schema.md` 的 AC10。

## 改写

只动表面。

允许：

- 语序微调、把中英夹杂改成通顺中文、去掉口头赘词
- 同义替换，前提是不引入新的步骤名或机制名

禁止：

- 换因果。因为 A 所以做 B，不能改成因为 C 所以做 D
- 换目标。原话里的目标不能换成原话没有的说法
- 添加原话没有的步骤名或机制名
- 用外部框架反填进 `expression`

自检口诀：改完之后，因果箭头还能否用原话里的词画出来。不能，改写失败，退回原话，或只做更小的表面改动。

上面的禁止针对模型改写。他亲手改过并确认的整句是新的 `expression`，不用来源原话否决那句。

不合格改写的样子：把来源里的「存下来、坚持、迭代、accumulate」收成「捕获—回看—改写／叠厚」。按 Jake 19:22 默认，锁定 expression 的因果是「存下来 → 积起来／滚复利」（已去掉「坚持迭代」半句）。后一句是转述，用来对照原因、手段和结果，不是要写入 `expression` 的金句。

## 保真自检

写 `expression` 之前，对每一条候选勾完再给他看。

1. 因果。原话里的「因为／所以／为了」是否还在，方向是否相同。
2. 目标词。原话里的目标是否保留，或仅为同义，没有换成新口号。
3. 步骤名。`expression` 里有没有原话没有的步骤名或机制名。有，就删掉，或挪到 `suggested_expression`。
4. 增量概念。多出来的解释、例子、机制，只能进 `suggested_expression`，或留在讨论备注里，不能进 `expression`。
5. 撞车。和 Journal 或短清单原话连续 20 个字相同吗。表面改写要避开整句粘贴。`origin` 为 `jake` 且选用的就是原话时除外，因为要留的就是这句。

这条撞车只约束 Idea 的 `expression`。公开稿仍按 content-core：不把周记原话写进标题、摘要、caption、卡片和正文。中心思想若就是那句原话，放在审批卡上。

任一题不过，不得把该句标成可交给 content 的 `expression`。

`suggested_expression` 不是 ideas-0.1 的节点字段。不进 frontmatter，不进 `history`，也不随节点落盘。它只出现在确认前的候选里。

## 短清单可公开

| 状态 | 含义 | 能否交给 content |
|---|---|---|
| 短清单「可公开」，或 `visibility` 为 `public-ok` | 他允许这句话作为公开素材来源 | 否。只解决可见范围 |
| `expression` 经他确认：保留原话，或他改过的整句 | 这句是对 content 的核心表达 | 是。须有确认记录：`history` 里 `by` 为 `jake`，表达与当前 `expression` 一致 |
| 改写句还没有再经他确认 | `candidate`，`origin` 为 `ai_extension` | 否 |

节点测试和演示不得用「短清单已批」跳过 `expression` 确认。未确认的改写句标明候选，待他确认。
