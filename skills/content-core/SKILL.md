# content-core

本技能是唯一的 content foundation：意识形态，以及 Idea 到内容的表达底线。不写某一平台的版式。

X 的写法在 `skills/content-x/SKILL.md`（X 运营加载。先采访，骨架闸门过了再写 X 长文母稿）。小红书在 `skills/content-xhs/SKILL.md`（内容写手加载，只从小红书展开 X 定稿）。公众号在 `skills/content-wechat/SKILL.md`（公众号编辑加载，从 X 定稿转换）。平台技能只叠渠道写法。旧 `skills/content/SKILL.md` 已停用，不能用它生产正文。

## 骨架闸门

写 X 长文正文之前须「采访完＋骨架填满（F1–F7 全勾）＋Jake 认可」。少一条，禁止生成正文，包括开头、提纲式正文、分段大纲和段落因果链。采访还在进行、作者自己觉得够了、F1–F6 已勾但 F7 没有，都不开写。他不回，不默认开写。「再想想」＝未过。冷读不在这一步。冷读只在成稿之后。

采访完：X 运营是主持人、采访者。这是现有岗位上的做法，不是新 bot，也不是新岗位。他就 Jake 已选定的本周 idea 组合采访并追问。采完，用他的答案写 X 长文。观点、经历、感受只用原话，展开按 editor「原话是骨头，写作者长肉」。怎么问、怎么追问和 F1–F7 的填满条文只在 `skills/interview/SKILL.md`，本技能不复述题干。

骨架填满就是 interview 里的 F1–F7 全勾。有一项没勾，退回继续问，不写正文。Jake 认可就是 F7。没听到「行」「就这样写」或「认可」，闸门不开。

整条顺序见 `docs/content/流程说明-20261026.md`，和本技能冲突时以本技能为准。

选题入口是本周 idea 组合：内容写手从本周已确认的 idea 池提出 A+B+C、A+B 或单独 A，Jake 定一个组合。禁止默认一篇 idea 直接一篇文。公众号和小红书不另选题，从已经写成的 X 定稿展开，不另写一篇底稿。好文章清单以后另接，本技能不写清单正文。

## 谁加载

- X 长文母稿、X Article、X 短帖：X 运营。加载 content-core + content-x。采访时再加载 interview。闸门过后写稿时再加载 editor。不加载 content-xhs、content-wechat。先当采访者，采访完、F1–F7 全勾、Jake 认可之后才写母稿。X 母稿的冷读、销项和去 AI 味由编辑（非作者）做，而且只在成稿之后；编辑加载 editor，不另写一套去 AI 味。冷读只用 editor 第 4 步「排」，加上第 6 步「查」的第 1–3 项和第 6–8 项；核对骨架和采访原话的第 1 步「准备」、第 6 步第 4 项「追溯检验」和第 5 项「M6 原味检验」，以及第 4 步 W9、M5、W12、W13 和默认顺序第 3–5 条里『是不是他讲过、他答过、他说过、有没有答过反方』的核对，第 6 步第 1 项里『小标题顺序是否跟采访题号一样』的核对，第 6 步第 6 项里『有没有编第一人称经历』的核实，留到销项时对照「我」判断出处表和第 1 步的材料索引，不在冷读里做。冷读做 W12／W13 时只看成稿结构（有没有一个论点、节里有没有「为什么／例子／对读者」、结尾是不是完整一句），不核对是不是他讲过。冷读只看结构有没有起、变、落，疑点列进报告。谁担任按团队分工定，在审稿报告上写明。
- 运营五条：X 运营。加载 content-x-ops。写长文和做运营可以分线程，一次只做一类。
- 小红书：内容写手。只加载 content-core + content-xhs。不写 X，不写公众号。选题组合由这一岗从本周 idea 池提出。小红书正文从 X 定稿展开，不另写底稿。
- 公众号：公众号编辑。加载 content-wechat，从 X 定稿转换。不另写新稿，不换中心思想，不另起选题。
- 配图：内容视觉。三渠道共用图按渠道裁（X 5:2；公众号封面 2.35:1、分享图 1:1；小红书按平台比例）。同 topic 只交一份配图需求包，写明各渠道画幅：X 作者交，小红书作者补页序，公众号编辑补公众号行。加载 content-visual。出图前先加载 canvas-design。
- 编辑审稿：编辑（非作者）。不写死是哪一个 bot。

字段、枚举、发布包、正文指纹和批准形状见 `skills/content/references/content-record.md`。`schema_version` 字面量是 `content-0.1`。时区 Asia/Hong_Kong，与上海时间同一钟面。

## 何时加载

先加载本技能，再按任务决定平台技能。采访只加载 `skills/interview/SKILL.md`。成稿怎么编只加载 `skills/editor/SKILL.md`；去 AI 味由 editor 加载 `skills/humanizer-zh/SKILL.md`。作者不拿 humanizer-zh 代替本技能。编辑审稿也不在本技能复述模式清单。interview、editor、humanizer-zh 都不是平台技能，不代替 content-x，也不把 content-xhs 或 content-wechat 带进只要 X 的这一轮。

任务是写 X、X Article、X 长文或 X 短帖，并且不是整周多渠道发布包、也不是明确三版交齐：由 X 运营加载。加载顺序是 content-core → canvas-design（仅出图之前）→ content-x。禁止在这一轮、这一写作上下文里 Skill load `content-xhs` 或 `content-wechat`。内容写手和公众号编辑不写这一轮。这种任务不套用「一次交齐」的三版要求，只交 X。点名只要 X 时，即便同时说了「写帖」「做内容」或 `/content`，仍走这一条。写 X 的正文排版以 content-x「写法」为准。该节已点选的条和本节编号清单、段长、小标题密度、收束冲突时，以 content-x 为准，不把旧排版当成硬门槛退稿。

任务是整周多渠道发布包，或他明确要三版交齐：他说「做内容」「选题」「写帖」「发布包」或 `/content`，以及作者出这一周的草稿，只要不是上一条的只要 X，都算这一包。X 版由 X 运营在 content-core 之后加载 content-x，先过骨架闸门再写。小红书由内容写手在 X 定稿之后加载 content-xhs，从定稿展开。公众号由公众号编辑加载 content-wechat，从 X 定稿转换。内容写手不加载 content-x，也不加载 content-wechat。生成任何封面、配图、插图、卡片或版式之前，必须先加载并遵守 `skills/canvas-design/SKILL.md`。一次交齐三版是三个渠道的审批卡都交齐，一个渠道一张，三张卡都交团队统一出口（现为 PM·总协调）转他。没有 X 定稿，不写另外两版。不出图的草稿不必先加载 canvas-design；一旦出图，必须先补上 canvas-design，再出图。缺任一版，不得交卡。

加载顺序（只要 X，X 运营）：content-core → canvas-design（仅出图之前）→ content-x。

加载顺序（小红书，内容写手）：content-core → canvas-design（仅出图之前）→ content-xhs。不加载 content-x，不加载 content-wechat。

加载顺序（公众号，公众号编辑）：content-core → content-wechat。从 X 定稿转换，不另写新稿。不加载 content-x 来重写定稿。

加载顺序（整周包或三版交齐）：三张审批卡一次交齐，一个渠道一张。X 运营只走 content-core → content-x，先过骨架闸门再写。X 定稿之后，内容写手才走 content-core → content-xhs，公众号编辑才走 content-wechat。配图由内容视觉按 content-visual 按渠道裁。出图之前由出图的那一岗加载 canvas-design。

canvas-design 是出图用的审美层，不是第四个内容主技能。它没有中文字体，没有 5:2、3:4、21:9，也不产公众号 HTML。这三处只在平台技能里做薄适配，不把平台技能加厚成另一套主技能。

只出某一个平台的样例时，仍先加载本技能；出图前加载 canvas-design；再只加载那个平台技能。样例只按该平台技能写，不用别的平台稿改写充数。X 样例同样禁止加载 content-xhs 或 content-wechat，也要先过骨架闸门。小红书和公众号仍按各自技能交卡，都从 X 定稿展开，不另起底稿。

本技能加载的就是这套 foundation。写 X 长文先过「骨架闸门」，再过下一节「foundation 硬规则」里适用的条，和「生成流程」，然后才按平台技能写版式。「写手五条」里的可选骨架优先级低于主线，也不能代替骨架闸门。

普通聊天不选题、不出稿。

## foundation 硬规则

写本轮要交的版本之前，先过适用的条。五条都在。全平台过第 1 条和第 5 条。写 X 再过第 2 条。写小红书再过第 3 条。写公众号再过第 4 条。只要 X 时，不因没有小红书或公众号稿而缺条。缺了本轮适用的一条，不得交卡。配图张数和渠道版式仍在对应的平台技能，这里不复述。出图审美在 canvas-design，不在这里复述。

### 1. anti-AI-slop（全平台）

禁止模板腔、空转句、overrated 或万能开场，包括「清楚过几天就糊了」这一类，以及正确的废话起势。模板腔、空话、标题和小标题怎么改，只按 `skills/humanizer-zh/SKILL.md`，不在这里另列模式。把采访编成文只按 `skills/editor/SKILL.md`。

开门见山，直接说事儿。

长文要有 deeper thought：看法写清为什么，机制说透。说透机制的推演用文章叙述的口气写，或明写这是推论，不用「我」认定，论证可以对读者说「你」，每条推论只标一次，不逐句加「推想」「推测」之类的标记（见「材料」节）。口语、像真人说话仍要。仅口语不过关。深度和去 slop 是底线。不靠假设或外推把不贴的 Fact 接进来。

### 2. X

配图保留 1–3 张，服务逻辑链。Articles 全宽真图等版式仍在 content-x。

行文必须更深、更少 slop。仅「口语自然」不过关。

### 3. 小红书

必须有 visual aid / explanation：解释性配图或图示，类似 X 那种服务逻辑链的说明图。

禁止只靠纯字卡或纯文字卡片交差。

### 4. 公众号

禁止「清楚过几天就糊了」及同类 AI 或 overrated 起势。

开门见山。第一段就直接说一个真实场景。论文、RCT 和期刊名不放在第一句。

### 5. 规则不进正文

本技能的句子是给作者的写作指导。不得把规则原文，或改头换面后的规则，写进读者正文。例如不得出现「清单只放这里」「研究放在对号入座之后」「失败画面」这类给作者看的话。

未定义的自造词禁用。新概念第一次出现，必须用读者懂的话讲清楚。

## 一次交齐

一次交齐三版只在两种任务里适用：整周多渠道发布包，或他明确要三版交齐。同一 topic 仍是一个渠道一张审批卡（X、公众号、小红书各一张），三张一次交齐。各卡由作者交统一出口（PM·总协调）转他，出口不合卡、不改稿。顺序是：X 运营先过骨架闸门，写成 X 定稿；小红书由内容写手从这版 X 定稿展开；公众号由公众号编辑从这版 X 定稿转换。三版分别按各自平台技能写。本技能不生产正文。没有 X 定稿，不得写另外两版。缺任一版，不得交这一批卡。

任务只要写 X、X Article、X 长文或 X 短帖：不加载 content-xhs 和 content-wechat，不要求另外两版同卡。只交 X。

小红书或公众号自己的任务仍按该平台技能交该版。本段不改它们的版式。

## 禁止 Journal 原话

不得把周记或私人日记里的句子原话写进 post。标题、摘要、caption、卡片和正文都算。

「周记里已经写清的句子直接引用」已废止。

写进公开稿的意思，必须来自他已确认的 `expression`：Idea 里他确认的整句，或讨论里他确认的整句。测试改写、未确认的 `suggested_expression`、未经他在骨架上认可的模型自拟的 paraphrase，都不能顶上。公开稿仍然不得粘贴周记原话。中心思想若就是那句原话，只放在审批卡上，不写进标题、摘要、caption、卡片和正文。Idea 文本本身也不整段粘贴 Journal。

出处指向 Idea id 或讨论确认句。记录里的 `journal:` 只作出处指针，不把那段原文当正文。

评新闻和讲观念交卡时都用「逻辑链」一节的那条链。正文沿主线写，不把这条链印成目录。「写手五条」的骨架可选，优先级低于主线。讲观念的经历必须是已确认之后的叙述（来自 Idea 里他确认的 `expression`，或讨论里他确认的整句），用自己的话转述，不是 Journal 粘贴，也不是未确认的改写。正文素材只从他指明的 `💡 Ideas/` 卡和 Fact 取，与「材料」节一致；不打开 Journal 摘句，不用周记原文，也不把带日期的事件当材料。第一手案例只转述 Idea 卡上已有的判断和场景，不贴周记或日记原句。

交卡前做撞车检查：把本轮要交的全部公开文字与可用的 Journal 对照。整周包或三版交齐时，三版都查。只要 X 时只查 X。去掉空白后，仍有连续 20 个字符相同，即红，不得交。

## 深度

配图说明、卡片文案和正文阐释须达到专业自媒体 / essay 编辑水准。

禁止看图写话、标签堆砌、正确的废话、无推论的罗列、「因为所以」断层、按日期罗列经历的流水账，以及 shallow、rocky、小学生说明文。

同时过 foundation 硬规则的 anti-AI-slop。长文要有 deeper thought：看法写清为什么，机制说透。口语、像真人说话仍要。仅口语不过关。不靠假设或外推把不贴的 Fact 接进来。

成稿之后的审稿只走下一节。不另挂外部 copy-editor，也不再做一轮作者自己的 copy-edit。

## 编辑审稿

作者写稿。编辑（非作者）审稿。作者不能自审。编辑可以由人担任，也可以另接专职编辑技能。本技能不写死是哪一个。

冷读只在成稿之后。采访进行中、骨架未填满、Jake 还没认可骨架、或者正文还没写成的时候，不做冷读，也不把冷读当成开写的许可。

顺序固定：采访完＋F1–F7 全勾＋Jake 认可 → 作者写稿 → 编辑（非作者）冷读并出报告 → 作者按报告逐条改并回应 → 编辑确认销项 → 才交下一步验收。

编辑（非作者）在一份新的上下文里冷读。作者不进入这份上下文。不放入 brief、Idea、骨架和写作过程。只放入成稿和骨架认可的中心思想一句。作者的段落因果链和「我」判断出处表也不放入。成稿本身标明发在哪个平台，以及写法是 essay 还是 How to（只标这几个字，不附骨架）。

编辑先用一句话复述全文在说什么，再和骨架认可的中心思想对照。这句复述取读完全文之后的重点：前两段能复述出中心，复述成术语或套话的不算；读完把重点说成工具名、步骤、产出或套话的，算对不上。对不上，直接判红退回，不进入逐句修改。判红的报告要引用对不上的原文片段。对得上之后再查因果和吸引力。因果：编辑不拿作者的链，自己从成稿逐段写出「这段证明什么、和上一段是因为／所以／但是／于是哪一种」。相邻两段只有时间先后或并列（流水账），或者写了因果但成稿里撑不住，算必修，要引用这两段的原文片段。吸引力：停刷测试、首段是否是真实场景、是否至少有 1 个数字或案例、读者能带走的东西是否写在叙事里。成稿标明 How to 的，冷读那一句仍须是骨架认可的中心思想，不是工具名、脚本名或七步怎么跑；复述落在「每步做什么、用什么、产出什么」上的，直接判红，引用被读成流程的原文。对得上之后再查：为什么和判断的篇幅要明显压过脚本名和产出物罗列；步骤若出现，要写为什么、并串回中心思想，没有为什么的算不过。禁止用「每步做什么、用什么、产出什么」当主骨架冲淡中心。读完能不能照着做可以看，不与中心复述并列，写全步骤而中心被盖过的，不算过。任何一项不过算必修，要引用原文；没改完、编辑没销项，不得交卡。

对得上中心之后，先写论证图，再写小标题朗读测。两块缺一，这份冷读报告无效，不得当作已冷读。论证图：编辑只看成稿，不看骨架，也不拿作者的段落因果链，写出论点、各分论点，以及每条分论点对应的证据原文。写不出论点或任一分论点，或者写出来的证据只是把主张换个说法，判红退回，引用原文，不进入逐句修改。小标题朗读测：逐条小标题判两问，像不像人会说的话，是不是口号。对仗句式（「不是…而是」「X不等于Y」「…才…」）算口号，标必修，引用原文。判断句小标题下面 3 段内指不出证据原文的，标必修。论证图和小标题朗读测各写一句，对着 `skills/content-core/references/exemplars.md` 的 E1–E5 比这篇更接近哪一篇。

对得上之后，按 `skills/editor/SKILL.md` 审结构：冷读只用第 4 步「排」，加上第 6 步「查」的第 1–3 项和第 6–8 项；核对骨架和采访原话的第 1 步「准备」、第 6 步第 4 项「追溯检验」和第 5 项「M6 原味检验」，以及第 4 步 W9、M5、W12、W13 和默认顺序第 3–5 条里『是不是他讲过、他答过、他说过、有没有答过反方』的核对，第 6 步第 1 项里『小标题顺序是否跟采访题号一样』的核对，第 6 步第 6 项里『有没有编第一人称经历』的核实，留到销项时对照「我」判断出处表和第 1 步的材料索引，不在冷读里做。冷读做 W12／W13 时只看成稿结构（有没有一个论点、节里有没有「为什么／例子／对读者」、结尾是不是完整一句），不核对是不是他讲过。冷读只看结构有没有起、变、落，疑点列进报告。再按 editor 加载的 `skills/humanizer-zh/SKILL.md`「本仓库审稿输出」出报告。区块格式只在那份技能里，这里不复述。不用只出终稿的内嵌模式。骨架认可的中心思想一句作为输入，和成稿一起交给它。豁免只限他本人的原话、他确认过的 expression、骨架认可的中心思想原句：这三样按原文进正文，不归去 AI 味改写，三连检查对这几句豁免。模型写的方向卡分论点、小标题和其他卡面句，他回过「行」也不豁免。正文其他句子不跟着写三连。终稿只作参考，由作者改。编辑不代写，也不把终稿直接换成正文。

报告固定从这几块里写，不许只写「已审无问题」：

1. 复述：读完全文后的重点，一句话。
2. 对照：读完全文后的重点对得上骨架认可的中心思想，或判红退回。前两段写了中心、读完重点却是步骤、工具或套话的，判红。前两段复述成术语而不是中心的，也判红。判红时引用对不上的原文片段，报告停在这里，不写下面各块。对得上之后，同一块写还原出的段落链，再写吸引力四项（How to 稿另写冷读复述是不是中心思想那一句、为什么和判断是否压过脚本名和产出物）；不过的标必修。
3. 论证图：只看成稿写出论点、各分论点，以及每条对应的证据原文。写不出，或证据只是把主张换个说法，判红退回，引用原文，报告停在这里，不写下面各块。这一块写一句和 `skills/content-core/references/exemplars.md` 的 E1–E5 比：证据是不是放在主张下面。
4. 小标题朗读测：逐条小标题写两判，像不像人会说的话，是不是口号。对仗句式（「不是…而是」「X不等于Y」「…才…」）算口号。判断句下面 3 段内指不出证据原文的，标必修。每条引用小标题原文。再写一句和 E1–E5 比：小标题更接近哪一篇的问句、话题、自白，或有证据撑住的判断句。
5. 论证图对得上之后，才按 `skills/humanizer-zh/SKILL.md`「本仓库审稿输出」写报告。终稿区块只作改法参考，正文由作者改。有逻辑风险时的确认项、复跑和无必修才交卡，都按那一节，不在这里复述。作者按审稿改完、编辑销项之后，由同一位编辑（非作者）对改后的终稿再跑一遍；这一遍又有问题的，列给作者改，编辑再看一眼。交卡用的是作者改后、编辑复跑无必修的那一版。
6. 论证图对得上之后，再按 `skills/humanizer-zh/SKILL.md` 的「审稿三条」核对，条文不在这里复述。每条问题都引用成稿里的原文片段。没有命中时，也要引用至少一处核对过的原句，并说明为什么留下。要交卡的报告，这六块都要有。缺论证图或小标题朗读测，不算有效冷读报告。对照是对得上，论证图不是判红，吸引力四项（How to 稿已写明冷读复述是中心思想那一句，且为什么和判断压过脚本名和产出物）已写明。

作者对每条【需作者确认】回应「已改（附新句）」或「不改（附理由）」。这是回应，不是销项。作者不能自销项。只有编辑（非作者）能销项。编辑接受该条回应后，写明已销。编辑不接受，就退回作者，不进入下一步验收。

审稿报告、作者的逐条回应、编辑销项，随交卡一起交。

## 生成流程

写正文之前按这五步，顺序不换：本周 idea 组合 → 采访 → 把答案收成骨架 → 采访完＋F1–F7 全勾＋Jake 认可 → 才写正文。逻辑链和交卡用同一步。expression 没有确认，看法没有确认，角度还没按第 1 步取定，或采访未完、F1–F7 未全勾、或 Jake 未按 F7 说可开写，不得写 X 长文正文（含开头、提纲式正文、分段大纲、段落因果链）。冷读不在这五步里，冷读只在成稿之后。

1. 先定本周 idea 组合，再在采访里把中心收成一句话。内容写手从本周已确认的 idea 池提组合，只允许 A+B+C、A+B、单独 A。Jake 选定一个组合，这个组合是本篇原料。禁止默认一篇 idea 直接一篇文。公众号和小红书不另选题。没有他选定的组合，停在选题，不采访，不写正文。这篇要表达什么，写成一句话。可以有两层：底层是做法，深一层是它对人和认知意味着什么；两层是同一主张，不把两三件事拼成复合句。两层都须出自他确认的 expression 或讨论原话，不加他没说过的机制。读者读完应能复述这一句。中心思想由已确认的 `expression`（Idea 里他确认的整句，或讨论里他确认的整句）写成一句读者读完能复述的话，经骨架认可；expression 本身不改。没有这句 expression，就停在选题，不写正文。禁止用测试改写、未确认的 `suggested_expression`，或未经他在骨架上认可的模型自拟的 paraphrase 顶替这句，也不能拿来当中心思想。也禁止把 Idea 收成原话没有的机制名，再拿来当中心思想。expression 确认后、骨架交他认可之前，同一个 expression 至少出 3 个角度候选，其中至少 1 个是「重新定义问题」型。用四测打分：停刷、压缩成一句、非共识、与读者相关，取最高分的角度；作者自己取定，不交他选。取定的角度体现在骨架的中心写法、标题和开场上，不另上卡；骨架认可后不重做，只有他改了中心思想、要重看骨架时才重排。expression 锁死不动，切入点可以换。这句中心思想只写一个主张。连同分论点带到第 4 步的骨架等他认可：2–3 条（F3）。每条是可独立成立的人话判断／态度，另推一环，不复述中心，不写愿望句，用经历对上中心环节；每条点名至少 1 件读者看得见的证据，并写 1 条真实读者疑问。E1–E5 的对照放在成稿后的冷读，不在这一步做。
2. 拿中心思想对照相关 Fact。Fact 必须直接支撑这一句。要靠假设或外推才接得上的，不算相关：不引，不硬借。讲观念可以没有外部 Fact，但必须带至少 1 个具体案例（场景、数字、改前改后），案例和 Fact 一样，必须直接支撑中心思想，靠外推才接得上的不用。优先第一手：从他指明的 `💡 Ideas/` 卡取场景和判断，用自己的话转述，禁止编造，也不贴日记原话，更不打开 Journal；没有第一手时，可用可查证的外部案例代替，标明出处；不引与中心无关的名人、名言或名人案例撑场面；外部人物只在他的事实直接支撑中心时出现，并标明出处。两样都没有时，他在讨论或骨架上确认过的原话可作这一分论点的论据，转述，注明出自哪次确认；连这个也没有才退回 intake 补料，不硬凑，不开写。素材范围与「材料」节一致。评新闻要有一条直接支撑中心思想的事实，附链接和日期。
3. 写出我们对这条 Fact 或这段已确认之后的经历的态度和看法：同意、反对、补充或限定，并写为什么。来源必须是已确认的 `expression`，或已确认的讨论句。没有确认过的态度，就停在选题，不写正文。

## 逻辑链

交卡写出下面几行，用来看见缺环。expression、骨架认可的中心思想、我们的看法、结论，缺一不交。评新闻缺直接相关的 Fact，不交。讲观念没有外部 Fact 时，Fact 那一行写具体案例，不留空，也不另借一条不贴的 Fact。案例要有场景、数字或改前改后，并标明第一手或外部出处。看法没确认，这一行不能由作者现编。第一行只能是已锁定的 `expression`。第二行是骨架上他确认的中心思想一句，读者读完应能复述这一句。

## 写手五条

这五条是写作要求，执行的人是作者。审稿的人是编辑（非作者）。这里不另设角色。

这五条不是另一条必填链。全文先满足「生成流程」和「骨架闸门」。本节说的骨架是「处境 → 误判 → 机制 → 最小动作 → 边界」，可选。它不是写 X 长文前的内容骨架（F1–F7）。审批卡上的逻辑链仍按上一节写，不印成目录。

「处境 → 误判 → 机制 → 最小动作 → 边界」只在这篇用得上时才用，优先级低于主线。不用这五步，也可以交。用了，也不为补齐某一步去编内容。

1. 选题先有中心思想一句，再可以写读者处境。禁止用 RCT、方法名或期刊名开题。
   自检：候选里有已确认的中心思想一句。出现 RCT、方法名或期刊名当入口，即不过。

   自检：主线完整时，不因为缺了骨架里的某一步而不过。为补骨架编了反方、经历或三步清单，即不过。用 01/02/03 当全文骨架，即不过。写 X 时，不因编号出现在最小动作之外而不过。其他渠道：编号清单出现在最小动作之外，即不过。

   自检：前两段之内看不出这篇要回答什么，或者用「这篇想讲清楚……」「下面讲……」「读完你会……」式预告顶替，即不过。出现不可核验的夸张收益、恐吓式落后、没有下文的悬念，或用学术名词当钩子，即不过。

同 topic 三版只改入口句，不改核心论点。禁止三版共用同一个学术标题。平台差别是长度和入口，不是深度开关。下面是各平台入口，不是必填骨架。和主线冲突时，以主线为准。

- X：首句、标题、段落、列表和收束按 content-x「写法」。小标题不用 01/02 当全文目录。问句或反转可以，不堆方法名。收藏或回复只给实质理由。不在结尾提问求回复，也不求转发或分享。

## 材料

读他指明的 `💡 Ideas/` 和 Fact。Fact 没有默认目录，不猜路径，不新建目录。写 How to、且做成物本身就是中心时，骨架上为支撑这句中心而点名的仓内文件（README、skill、脚本、workflow 的路径）算他指明的 Fact，只引卡上点名的那几个，附路径，仍按生成流程第 2 步核对它是否直接支撑中心思想；不靠多引脚本把认知主张写成流程。不打开 Journal 摘句。不扫私人目录来补材料。

核心表达必须是他确认过的那一句 `expression`：Idea 里他确认的整句，或讨论里他确认的整句。中心思想由这一句写成一句读者读完能复述的话，经骨架认可；expression 本身不改。不另写一句未经确认的中心思想。测试改写、未确认的 `suggested_expression`、未经他在骨架上认可的模型自拟的 paraphrase，都不能写入 `expression`，不能当中心思想，也不能当成我们的看法。不得把 Idea 收成原话没有的机制名当中心思想。中心思想还没确认，或看法还没确认，就停在选题，不写正文。

Fact 只引用直接支撑中心思想的。要靠假设或外推才接得上的不引。讲观念可以没有外部 Fact，但具体案例按生成流程，没有就不开写。不编造他的观点或经历。AI 的推演保持为建议，不写进他的口气：正文里以「我」说出的判断和经历，必须能指回他确认的 expression、Idea 卡或他确认过的原话；指不回的，改成叙述口气或明写是推论，否则删掉。作者交成稿时另附一张「我」判断出处表（每句一行：原句｜expression、Idea 卡路径或确认原话及确认时间），不进冷读上下文；编辑先按成稿和中心思想纯读出报告，销项时再拿这张表逐句核，指不回的列必修。

## 六步

每周约 2 个 topic。候选可以更多，给他换。他只要 1 条，或这周没有能公开的材料，就按实际条数交，不编一条凑数。不全量塞「评论过的话题」。

要他拍板的有四处：做哪一个本周 idea 组合、骨架（采访完后的 F1–F7）、短清单、这一版批不批。骨架不问素材能否公开。成稿交到审核发布时，正文用到的第一手素材按短清单问；不回，就保持不公开。不必六步各批一次。

他中途来问，就从已经做到的那一步接上。周日 20:00 前，编辑已经确认、自检也通过的，才交出发布包。周一 10:00 把各渠道审批卡（一渠道一张）交统一出口转他。编辑还没确认，或自检没过，不要为了赶点交卡。本技能不建定时任务。

### 1. 发现选题

内容写手从本周已确认的 idea 池提组合，只允许 A+B+C、A+B、单独 A。不要把他评论过的话题全部放进候选。禁止默认一篇 idea 直接一篇文。公众号和小红书不在这一步另选题。

每个组合写明用了池里哪几条、读者处境、受众问题、缺什么材料。角度不在这一步定死：expression 确认后按生成流程出候选，作者按四测取最高分，不把确认句当成唯一切入。组合里已经确认的 `expression` 才是原料；expression 本身不改，中心一句留到采访里收，经骨架认可。还没确认的，包括测试改写和 `suggested_expression`，标成待确认，停在选题，不写正文。禁止用 RCT、方法名或期刊名当候选标题。禁止把 Idea 收成新机制名再写成这一句。X 上的热门只能另起一行写成「参考」。参考不是他的观点，也不拿来淘汰他的材料。一条热门下面没有他的观点，就不跟那条热门做题。

这一步的产物是候选组合。`origin` 为 `ai_extension`，除非题目是他先提出来的。

### 2. 确定选题

他选择、改写，或接受某一个组合。接受组合不等于确认一句模型改写。组合只允许 A+B+C、A+B、单独 A。产物要写明目标、受众、核心表达、我们的看法、题型，以及组合里是哪几条 idea。核心表达必须是组合里他已确认的 `expression`。标题按写手五条第 2 条，留到闸门打开后回填。

题型只有两种。评新闻是一条直接支撑中心思想的事实，加上已确认的看法。讲观念是一个概念加上至少 1 个具体案例，可以没有外部 Fact。

组合还没选定，或中心思想、看法还没确认，就停在选题，不采访，不写正文。

### 3. 内容策划

X 运营当采访者，就他选定的组合采访、追问。怎么问只在 `skills/interview/SKILL.md`，这里不复述题干。采完才把答案收成骨架。写 brief：结构、引用组合里哪几条 Idea、引用哪条直接支撑中心思想的 Fact（讲观念没有外部 Fact 就写明不引）、用哪个具体案例（场景、数字或改前改后；第一手优先，外部案例写出处）、哪种题型、排在哪一次。产物是这份 brief。靠假设或外推才接得上的材料不写进 brief。brief 最后一项是骨架（F1–F7 全勾，按生成流程第 4 步）。采访未完、F1–F7 未全勾、或 Jake 未按 F7 说可开写，不写「骨架认可」，不写段落因果链，不写正文。采访完且 F1–F7 全勾且他已说可开写之后，brief 开头补上「骨架认可」，再写段落因果链（生成流程第 5 步）。

缺材料，或立场和已确认的表达对不上时，一次只问一个问题。可以问：不认同的是结论还是条件；有没有经历过相反的情况；这件事会不会改变做法。这些问话是采访，不是开写。他补上的话按确认句记，不把 Journal 原句抄进 brief。反例用来分清真分歧和措辞。讲观念没有第一手具体案例，也没有可查证的外部案例，就退回 intake 补料，不开写。没有确认过的看法，就不写正文。

### 4. 内容生产

采访已经完成，F1–F7 已经全勾，Jake 已经按 F7 说可开写，brief 开头有「骨架认可」，brief 里点名的缺口也补上之后，才写段落因果链和正文。正文不得超出「骨架认可」里的 F1–F7；「本篇不用」里列的，正文一条也不出现。

只要 X（写 X、X Article、X 长文、X 短帖）：由 X 运营按 `skills/content-x/SKILL.md` 写，并过本轮适用的 foundation 硬规则和生成流程。内容写手和公众号编辑不写这一轮。写手五条里的可选骨架可用可不用，它不是内容骨架闸门。生成封面或配图前先加载 canvas-design。禁止加载 content-xhs、content-wechat。只交 X，即可进入审稿。每一段都要服务主线的某一环。不为凑写手五条编反方、经历或三步清单。

整周多渠道包或明确三版交齐：X 运营先按 `skills/content-x/SKILL.md` 写成 X 定稿。没有这版定稿，不写另外两版。内容写手再按 `skills/content-xhs/SKILL.md` 从 X 定稿写小红书，公众号编辑再按 `skills/content-wechat/SKILL.md` 从 X 定稿转公众号。写手五条里的可选骨架可用可不用。生成封面、配图或卡片前先加载 canvas-design。三张审批卡一次交齐。缺任一版，不得把这一批卡交出去。X 长文成稿之后就可以冷读，不等另外两版写完。每一段都要服务主线的某一环。不为凑写手五条编反方、经历或三步清单。

### 5. 审核发布

全程顺序不换：本周 idea 组合 → 采访完 → 骨架 F1–F7 全勾 → Jake 按 F7 说可开写 → 段落因果链与成稿 → 编辑冷读与销项（只在成稿后）→ 去 AI 味对终稿再跑（编辑审稿第 3 步）→ 写法对照按终稿重做，对照 Academy 原文（BREAKDOWN 与 01-articles-guide，见 content-x「写法」），不对照 content-x 的转述；交稿前那一版只作预对照 → 出图（canvas-design）→ 建 X Articles 草稿前核对硬门：同一终稿 sha 上已有复核（销项后编辑对这份终稿复跑且无必修的报告，文件名 `复核-*.md`；销项前的冷读不能顶上）、去 AI 味复跑、写法对照三份文件，三份写明的 sha 与终稿一致 → 草稿回执列出这三份路径和这个 sha → 排进 Articles 阅读页出预览截图 → 验收交卡。少一份，或 sha 不一致，不得建草稿。作者交成稿之后，先由编辑（非作者）按「编辑审稿」冷读。作者逐条回应。编辑确认销项之后，才做下一步验收：三层过滤、foundation 硬规则、交卡逻辑链、Journal 连续 20 字撞车和排版自检。出过图的，还要核 canvas-design 已加载，以及画面、背景、字体协调。公众号版由公众号编辑从已销项的 X 母稿转来，不另走冷读，审稿报告、作者回应和销项用 X 母稿那一份；上面的验收照做。通过之后，按 `skills/content/references/content-record.md` 的发布包交卡。审稿报告、作者回应和编辑销项附在卡上。「骨架认可」一节也附在审批卡上。验收时对照：正文的中心思想、分论点是否都在确认记录之内；正文段落和 brief 里的段落因果链是否一致。成稿用到的第一手素材在这一步按「敏感五类与短清单」问公开；不回就保持不公开，没批的不进公开稿。一张卡一条内容。整周包或三版交齐时，一个渠道一张审批卡（X、公众号、小红书各一张）。只要 X 时，卡上只交 X。

交卡交到统一出口（PM·总协调），由出口请他回「收到」；当天没有，出口再提一次。还是没有，就说明他还没回「收到」。正式副本在 Google Drive「内容/草稿/{年-W周}/」（写成 ISO 周，例如 `2026-W42`）。不把发布包写到这台机器的本地磁盘。

他回「批 / 改 / 不要」。「批」只覆盖卡上写明的那一版。「改」按他的原话改，revision 加一，重新给卡。「不要」这条停止，不再出稿。

bot 不代发。

### 6. 反馈复盘

他亲自发完，并且口头确认发过之后，才把发布结果记成已发布。没有这句确认，就保持未确认。

发后约第 7 天，他若贴来数据和评论，整理进这条的复盘。他可以补咨询、客户或线下听到的反馈。客户和人名若属于敏感五类，只留在未公开的复盘里，不写进公开稿。两周后的按时率、批准率和改动次数由他或 CoS 看。本技能不拉平台数据。流量高低不改 Belief。不写 Cognition。复盘里新的问题可以交给 ideas，本技能不写 Idea 文件。
