# content-core

本技能是唯一的 content foundation：意识形态，以及 Idea 到内容的表达底线。不写某一平台的版式。

X 的写法在 `skills/content-x/SKILL.md`（X 运营加载，写 X 长文母稿）。小红书在 `skills/content-xhs/SKILL.md`（内容写手加载，只小红书）。公众号在 `skills/content-wechat/SKILL.md`（公众号编辑加载，从 X 母稿转换）。平台技能只叠渠道写法。旧 `skills/content/SKILL.md` 已停用，不能用它生产正文。

## 谁加载

- X 长文母稿、X Article、X 短帖：X 运营。加载 content-core + content-x。不加载 content-xhs、content-wechat。
- 运营五条：X 运营。加载 content-x-ops。写长文和做运营可以分线程，一次只做一类。
- 小红书：内容写手。只加载 content-core + content-xhs。不写 X，不写公众号。
- 公众号：公众号编辑。加载 content-wechat，从 X 母稿转换。不另写新稿，不换中心思想。
- 配图：内容视觉。三渠道共用图按渠道裁（X 5:2；公众号封面 2.35:1、分享图 1:1；小红书按平台比例）。加载 content-visual。出图前先加载 canvas-design。
- 编辑审稿：编辑（非作者）。不写死是哪一个 bot。

字段、枚举、发布包、正文指纹和批准形状见 `skills/content/references/content-record.md`。`schema_version` 字面量是 `content-0.1`。时区 Asia/Hong_Kong，与上海时间同一钟面。

## 何时加载

先加载本技能，再按任务决定平台技能。编辑审稿之前，编辑（非作者）加载 `skills/qu-ai-wei/SKILL.md`。作者写稿时不加载 qu-ai-wei 来代替本技能。qu-ai-wei 不是平台技能，不代替 content-x，也不把 content-xhs 或 content-wechat 带进只要 X 的这一轮。

任务是写 X、X Article、X 长文或 X 短帖，并且不是整周多渠道发布包、也不是明确三版交齐：由 X 运营加载。加载顺序是 content-core → canvas-design（仅出图之前）→ content-x。禁止在这一轮、这一写作上下文里 Skill load `content-xhs` 或 `content-wechat`。内容写手和公众号编辑不写这一轮。这种任务不套用「一次交齐」的三版要求，只交 X。点名只要 X 时，即便同时说了「写帖」「做内容」或 `/content`，仍走这一条。写 X 的正文排版以 content-x「写法」为准。该节已点选的条和本节编号清单、段长、小标题密度、收束冲突时，以 content-x 为准，不把旧排版当成硬门槛退稿。

任务是整周多渠道发布包，或他明确要三版交齐：他说「做内容」「选题」「写帖」「发布包」或 `/content`，以及作者出这一周的草稿，只要不是上一条的只要 X，都算这一包。X 版由 X 运营在 content-core 之后加载 content-x。小红书由内容写手在 content-core 之后加载 content-xhs。公众号由公众号编辑加载 content-wechat，从 X 母稿转换。内容写手不加载 content-x，也不加载 content-wechat。生成任何封面、配图、插图、卡片或版式之前，必须先加载并遵守 `skills/canvas-design/SKILL.md`。一次交齐三版是卡上三版都在。不出图的草稿不必先加载 canvas-design；一旦出图，必须先补上 canvas-design，再出图。缺任一版，不得交卡。

加载顺序（只要 X，X 运营）：content-core → canvas-design（仅出图之前）→ content-x。

加载顺序（小红书，内容写手）：content-core → canvas-design（仅出图之前）→ content-xhs。不加载 content-x，不加载 content-wechat。

加载顺序（公众号，公众号编辑）：content-core → content-wechat。从 X 母稿转换，不另写新稿。不加载 content-x 来重写母稿。

加载顺序（整周包或三版交齐）：卡上三版交齐。X 运营只走 content-core → content-x。内容写手只走 content-core → content-xhs。公众号编辑走 content-wechat。配图由内容视觉按 content-visual 按渠道裁。出图之前由出图的那一岗加载 canvas-design。

canvas-design 是出图用的审美层，不是第四个内容主技能。它没有中文字体，没有 5:2、3:4、21:9，也不产公众号 HTML。这三处只在平台技能里做薄适配，不把平台技能加厚成另一套主技能。

只出某一个平台的样例时，仍先加载本技能；出图前加载 canvas-design；再只加载那个平台技能。样例只按该平台技能写，不用别的平台稿改写充数。X 样例同样禁止加载 content-xhs 或 content-wechat。小红书和公众号自己的任务仍按各自技能交卡，本段不改它们的流程。

本技能加载的就是这套 foundation。本轮要写的版本先过下一节「foundation 硬规则」里适用的条，和「生成流程」，再按平台技能写版式。「写手五条」里的骨架按写法可选，优先级低于主线。

普通聊天不选题、不出稿。

## foundation 硬规则

写本轮要交的版本之前，先过适用的条。五条都在。全平台过第 1 条和第 5 条。写 X 再过第 2 条。写小红书再过第 3 条。写公众号再过第 4 条。只要 X 时，不因没有小红书或公众号稿而缺条。缺了本轮适用的一条，不得交卡。配图张数和渠道版式仍在对应的平台技能，这里不复述。出图审美在 canvas-design，不在这里复述。

### 1. anti-AI-slop（全平台）

禁止模板腔、空转句、overrated 或万能开场，包括「清楚过几天就糊了」这一类，以及正确的废话起势。

开门见山，直接说事儿。

长文要有 deeper thought：看法写清为什么，机制说透。口语、像真人说话仍要。仅口语不过关。深度和去 slop 是底线。不靠假设或外推把不贴的 Fact 接进来。

### 2. X

配图保留 1–3 张，服务逻辑链。Articles 全宽真图等版式仍在 content-x。

行文必须更深、更少 slop。仅「口语自然」不过关。

### 3. 小红书

必须有 visual aid / explanation：解释性配图或图示，类似 X 那种服务逻辑链的说明图。

禁止只靠纯字卡或纯文字卡片交差。

### 4. 公众号

禁止「清楚过几天就糊了」及同类 AI 或 overrated 起势。

开门见山。第一段就直接说一个真实场景。论文、RCT 和期刊名不放在第一句。

### 5. 规则不进正文

本技能的句子是给作者的写作指导。不得把规则原文，或改头换面后的规则，写进读者正文。例如不得出现「清单只放这里」「研究放在对号入座之后」「失败画面」这类给作者看的话。

未定义的自造词禁用。新概念第一次出现，必须用读者懂的话讲清楚。

## 一次交齐

一次交齐三版只在两种任务里适用：整周多渠道发布包，或他明确要三版交齐。同一 topic 一次生成 X、小红书、公众号三版，一个渠道一张审批卡（X、公众号、小红书各一张）。X 版由 X 运营写，小红书由内容写手写，公众号由公众号编辑从 X 母稿转换。三版分别按各自平台技能写。本技能不生产正文。缺任一版，不得交卡。

任务只要写 X、X Article、X 长文或 X 短帖：不加载 content-xhs 和 content-wechat，不要求另外两版同卡。只交 X。

小红书或公众号自己的任务仍按该平台技能交该版。本段不改它们的版式。

## 禁止 Journal 原话

不得把周记或私人日记里的句子原话写进 post。标题、摘要、caption、卡片和正文都算。

「周记里已经写清的句子直接引用」已废止。

写进公开稿的意思，必须来自他已确认的 `expression`：Idea 里他确认的整句，或讨论里他确认的整句。测试改写、未确认的 `suggested_expression`、未经他在方向卡确认的模型自拟的 paraphrase，都不能顶上。公开稿仍然不得粘贴周记原话。中心思想若就是那句原话，只放在审批卡上，不写进标题、摘要、caption、卡片和正文。Idea 文本本身也不整段粘贴 Journal。

出处指向 Idea id 或讨论确认句。记录里的 `journal:` 只作出处指针，不把那段原文当正文。

评新闻和讲观念交卡时都用「逻辑链」一节的那条链。正文沿主线写，不把这条链印成目录。「写手五条」的骨架可选，优先级低于主线。讲观念的经历必须是已确认之后的叙述（来自 Idea 里他确认的 `expression`，或讨论里他确认的整句），用自己的话转述，不是 Journal 粘贴，也不是未确认的改写。第一手案例从底稿或他的记录里取意思，不贴周记或日记原句。

交卡前做撞车检查：把本轮要交的全部公开文字与可用的 Journal 对照。整周包或三版交齐时，三版都查。只要 X 时只查 X。去掉空白后，仍有连续 20 个字符相同，即红，不得交。

## 深度

配图说明、卡片文案和正文阐释须达到专业自媒体 / essay 编辑水准。

禁止看图写话、标签堆砌、正确的废话、无推论的罗列、「因为所以」断层、按日期罗列经历的流水账，以及 shallow、rocky、小学生说明文。

同时过 foundation 硬规则的 anti-AI-slop。长文要有 deeper thought：看法写清为什么，机制说透。口语、像真人说话仍要。仅口语不过关。不靠假设或外推把不贴的 Fact 接进来。

成稿之后的审稿只走下一节。不另挂外部 copy-editor，也不再做一轮作者自己的 copy-edit。

## 编辑审稿

作者写稿。编辑（非作者）审稿。作者不能自审。编辑可以由人担任，也可以另接专职编辑技能。本技能不写死是哪一个。

顺序固定：作者写稿 → 编辑（非作者）冷读并出报告 → 作者按报告逐条改并回应 → 编辑确认销项 → 才交下一步验收。

编辑（非作者）在一份新的上下文里冷读。作者不进入这份上下文。不放入 brief、Idea、方向卡和写作过程。只放入成稿和方向卡确认的中心思想一句。作者的段落因果链也不放入。成稿本身标明发在哪个平台。

编辑先用一句话复述全文在说什么，再和方向卡确认的中心思想对照。对不上，直接判红退回，不进入逐句修改。判红的报告要引用对不上的原文片段。对得上之后再查因果和吸引力。因果：编辑不拿作者的链，自己从成稿逐段写出「这段证明什么、和上一段是因为／所以／但是／于是哪一种」。相邻两段只有时间先后或并列（流水账），或者写了因果但成稿里撑不住，算必修，要引用这两段的原文片段。吸引力：停刷测试、首段是否是真实场景、是否至少有 1 个数字或案例、读者能带走的东西是否写在叙事里。任何一项不过算必修，要引用原文；没改完、编辑没销项，不得交卡。

对得上之后，按本库 `skills/qu-ai-wei/SKILL.md` 的普通模式出报告。上游是 [qu-ai-wei](https://github.com/LifelongLazyLearner/qu-ai-wei/blob/1d32e803f091ec90808a69683ebf49e8a970a5e7/SKILL.md)，commit `1d32e803f091ec90808a69683ebf49e8a970a5e7`，MIT。原文不改，见 `skills/qu-ai-wei/SOURCE.md`。不用内嵌模式。内嵌模式只出终稿，不出报告。方向卡确认的中心思想一句作为输入，和成稿一起交给它。qu-ai-wei 给出的终稿只作参考，由作者改。编辑不代写，也不把终稿直接换成正文。

报告固定从这几块里写，不许只写「已审无问题」：

1. 复述：一句话。
2. 对照：对得上方向卡确认的中心思想，或判红退回。判红时引用对不上的原文片段，报告停在这里，不写下面两块。对得上之后，同一块写还原出的段落链，再写吸引力四项；不过的标必修。
3. 对照对得上之后，才写 qu-ai-wei 普通模式的【门检】、终稿、【打磨报告】。有逻辑风险时列出【需作者确认】。
4. 对照对得上之后，再写下面三条。每条问题都引用成稿里的原文片段。没有命中时，也要引用至少一处核对过的原句，并说明为什么留下。要交卡的报告，这四块都要有，并且对照是对得上，吸引力四项已写明。

这三条用中文重述，来源是 cursor/plugins 的 pstack unslop（MIT）。不照搬英文，也不把该文件拷进本库：

- 说它做什么，不说感觉如何。一句话说不出具体指令、事实或数字，就删。
- 做作修辞。有直白说法时，不用比喻、格言、拟人，也不用只为了效果的短句。
- 过度压缩。不许电报体，不许没有主语或没有动词的碎句，不许用符号或箭头当缩写。写成完整句子。

作者对每条【需作者确认】回应「已改（附新句）」或「不改（附理由）」。这是回应，不是销项。作者不能自销项。只有编辑（非作者）能销项。编辑接受该条回应后，写明已销。编辑不接受，就退回作者，不进入下一步验收。

审稿报告、作者的逐条回应、编辑销项，随交卡一起交。

## 生成流程

写正文之前按这五步，顺序不换。逻辑链和交卡用同一步。expression 没有确认，看法没有确认，角度还没按第 1 步取定，或方向卡上的中心思想和论据还没经他确认，不得写正文。

1. 先定中心思想。这篇要表达什么，写成一句话。读者读完应能复述这一句。中心思想由已确认的 `expression`（Idea 里他确认的整句，或讨论里他确认的整句）写成一句读者读完能复述的话，经方向卡他确认；expression 本身不改。没有这句 expression，就停在选题，不写正文。禁止用测试改写、未确认的 `suggested_expression`，或未经他在方向卡确认的模型自拟的 paraphrase 顶替这句，也不能拿来当中心思想。也禁止把 Idea 收成原话没有的机制名，再拿来当中心思想。expression 确认后、动笔前，同一个 expression 至少出 3 个角度候选，其中至少 1 个是「重新定义问题」型。用四测打分：停刷、压缩成一句、非共识、与读者相关，取最高分的角度；作者自己取定，不交他选。expression 锁死不动，切入点可以换。这句中心思想连同主要论据，带到第 4 步的方向卡等他确认。
2. 拿中心思想对照相关 Fact。Fact 必须直接支撑这一句。要靠假设或外推才接得上的，不算相关：不引，不硬借。讲观念可以没有外部 Fact，但必须带至少 1 个具体案例（场景、数字、改前改后）。优先第一手：从底稿或他的记录里取，用自己的话转述，禁止编造，也不贴日记原话；没有第一手时，可用可查证的外部案例代替，标明出处；两样都没有就退回 intake 补料，不开写。评新闻要有一条直接支撑中心思想的事实，附链接和日期。
3. 写出我们对这条 Fact 或这段已确认之后的经历的态度和看法：同意、反对、补充或限定，并写为什么。来源必须是已确认的 `expression`，或已确认的讨论句。没有确认过的态度，就停在选题，不写正文。
4. 出方向卡，等他确认。纯文本，几行就行，不交图片，不交 md。卡上只写三项：中心思想一句（由已锁定的 expression 写成一句话，expression 不改）；主要论据 2–3 条，编号 1–3，每条一句；开场场景一句，写正文从哪个真实场景开始，第一手优先，括号注出处，不编；没有真实场景就写明缺，请他补。结尾一行：回「行」就按这个写；有意见直接改。他回「行」，或同义的明确同意，算方向确认。他有意见，按他的改法改中心思想或论据，照改后的写，不再重出卡；只有他改后的中心思想与原主张不同，才把这几项再回给他看一眼，等他回「行」再写。开场场景以他最后说的为准：确认之后他口头改了开场，或者说过开场可以由我们换、不必再问他，就照他后来的话办，不用另等「行」。换上的场景仍须真实发生过，第一手优先，括号注出处，不编。换了就当场写回「方向确认」的终版开场场景一句，并附改动时间（HKT）和他那句原话。他不回就一直等，不默认开写。他确认之前不写正文，包括标题、开头、提纲式正文、分段大纲。确认之后，brief 开头的「方向确认」只写：确认时间（HKT）、他回话原话、终版中心思想一句、终版论据 2–3 条、终版开场场景一句。这句确认过的中心思想用于逻辑链第二行、冷读输入和正文。已锁定的 expression 不替换。写作中途要换成另一个主张，就停笔，把新的中心思想和论据回给他看一眼，等他回「行」再写。
5. 方向卡确认之后，先写段落因果链，再写正文。一段写一行：「Pn｜这段证明什么｜和上一段：因为／所以／但是／于是」。P1 写开场场景；后面每段都要把中心思想往前推一步，和上一段只能是这四种关系之一，而且这层关系要有材料撑着，不为接上硬写因果。相邻两段只是「然后」「另外」「同一天」「前一周」这类时间先后或并列，就是流水账：合并、删掉，或调整顺序。多条 Idea、多段内容、多篇周记可以放进同一篇，但只当证据，按论证顺序排，不按日期排；日期可以留在段里当场景细节。论据 1–3 不是章节，不按论据分节。段落因果链写进 brief，只给作者和验收看，不上方向卡，也不进冷读。正文改了段落，链要跟着改。整周多渠道包或明确三版交齐时，三版都从这条主线展开；只要 X 时，只展开 X。禁止乱编：不为凑骨架编反方，不编经历，不编三步清单。

## 逻辑链

交卡写出下面几行，用来看见缺环。expression、方向卡确认的中心思想、我们的看法、结论，缺一不交。评新闻缺直接相关的 Fact，不交。讲观念没有外部 Fact 时，Fact 那一行写具体案例，不留空，也不另借一条不贴的 Fact。案例要有场景、数字或改前改后，并标明第一手或外部出处。看法没确认，这一行不能由作者现编。第一行只能是已锁定的 `expression`。第二行是方向卡上他确认的中心思想一句，读者读完应能复述这一句。

```
expression（已锁定，不改）
  → 中心思想（方向卡确认的一句；读者读完应能复述）
  → Fact 或具体案例（Fact 要链接和日期，并且直接支撑中心思想；讲观念可以没有外部 Fact，但要写明场景、数字或改前改后，并标明第一手或外部出处）
  → 我们的看法（同意 / 反对 / 补充 / 限定，加上为什么）
  → 结论（对读者意味着什么）
```

不是「事实加感想」两段拼盘。看法挂在中心思想上，也挂在直接相关的 Fact 或经历上。

这几行只写在审批卡上。不要把 expression、中心思想、Fact、我们的看法、结论写成正文的小标题或 H2。禁止用 01、02、03 这类编号章节当全文骨架。读者看到的推进是主线：每一段服务上面某一环，段与段的关系按生成流程第 5 步的段落因果链。

公众号由公众号编辑做：X 母稿 → `skills/content-wechat/SKILL.md` 缩版转换。版式和标题可调。嵌入和外链改成截图或文末注。不另写新稿，不换中心思想。X 的字数见 content-x。逻辑链是交卡底线。骨架不是交卡底线。

交卡时用这几行写出这条链，让缺环看得见。审稿报告和作者回应附在同一张卡上。

## 写手五条

这五条是写法，执行的人是作者。审稿的人是编辑（非作者）。这里不另设角色。

这五条不是另一条必填链。全文先满足「生成流程」。审批卡上的逻辑链仍按上一节写，不印成目录。

「处境 → 误判 → 机制 → 最小动作 → 边界」只在某种写法用得上时才用，优先级低于主线。不用这五步，也可以交。用了，也不为补齐某一步去编内容。

第 1、2、4、5 条的自检不过，不得交卡。第 3 条骨架不必备。第 4 条要求第一段写真实场景、正文不讲课，并禁论文开场；不要求每篇都走对号入座。

1. 选题先有中心思想一句，再可以写读者处境。禁止用 RCT、方法名或期刊名开题。
   自检：候选里有已确认的中心思想一句。出现 RCT、方法名或期刊名当入口，即不过。
2. 标题只放一个主张，带上对象、数字或结果之一。抽象金句不当标题。
   自检：标题里能指出那一个主张，以及对象、数字或结果是哪一个。两个以上主张，或只剩抽象判断，即不过。
3. 骨架可选，是「处境 → 误判 → 机制 → 最小动作 → 边界」。写 X 时，列表和编号按 content-x「写法」，可以出现在最小动作之外。其他渠道：用了骨架的话，1234 编号清单只出现在「最小动作」内部；不用最小动作时，正文不用 1234 编号清单。
   自检：主线完整时，不因为缺了骨架里的某一步而不过。为补骨架编了反方、经历或三步清单，即不过。用 01/02/03 当全文骨架，即不过。写 X 时，不因编号出现在最小动作之外而不过。其他渠道：编号清单出现在最小动作之外，即不过。
4. 第一段写「方向确认」里记的终版开场场景（他后来改过就以改后的为准，见生成流程第 4 步）：真实发生过，第一手优先，不编。用叙事带论证，让场景里发生的事推着论点走，写出日记那样的文学感；不用清单腔，不对读者讲课。若开头走对号入座，不超过 3 句。数据和论文不放在第一句。不要求每篇都走对号入座。
   自检：第一段不是真实场景，或者场景是编的，即不过。正文里出现对读者讲规矩、给可以照抄的步骤这类讲课段，即不过。第一句是论文、期刊、样本量或百分比，即不过。不要求正文出现某句固定说法。
5. 第三段之前，让读者从开场场景里看出这篇要回答什么、读完能拿走什么，用叙事里的话带出来，不写「这篇想讲清楚…」这种预告。学：反转冲突，场景里自然带出的前后对照。不学：消灭90%、效率翻倍、FOMO 恐吓、空悬念、学术名词当钩子。
   自检：第三段之前看不出这篇要回答什么，或者用「这篇想讲清楚…」「下面讲…」式预告顶替，即不过。出现不可核验的夸张收益、恐吓式落后、没有下文的悬念，或用学术名词当钩子，即不过。

同 topic 三版只改入口句，不改核心论点。禁止三版共用同一个学术标题。平台差别是长度和入口，不是深度开关。下面是各平台入口，不是必填骨架。和主线冲突时，以主线为准。

- X：首句、标题、段落、列表和收束按 content-x「写法」。小标题不用 01/02 当全文目录。问句或反转可以，不堆方法名。收藏或回复只给实质理由。不在结尾提问求回复，也不求转发或分享。
- 小红书：人群或结果，加上短时限或避坑。封面第一行要对号入座。入口词用读者会搜的口语。第一段写一个真实场景，第三段前写出读完能拿走什么。页与页是因果或时间。结尾指向收藏。
- 公众号：个人经历或判断，标题大约 20–28 字，仍然禁止方法名开场。摘要承接处境。第一段写一个真实场景。结尾回收开头的问题，并给出可执行的标准。

反常识可以写。正文前一两屏必须兑现。标题承诺颠覆、正文只复述定义，不过。

节奏：结论段短，解释段可以长。禁止连续五段同一套「主题句加子弹」。转场写判断句，不写「接下来介绍第二节」。读者能带走的东西写进叙事：一个前后对照，或者一个读者今天就能照做的动作，从已有材料里来；不在文末另附清单或模板，没有就不硬加。结尾收在主线上：写清结论在哪停，或给一个读者今天能做的下一步，同时给出收藏或回复的实质理由，点明读者要留下的那一件，或值得接着说的那一点，不写成提问求回复，也不求转发。合集可以分块。不是合集，不要用一、二、三、四当全文骨架。假留白（整页金句、空洞反问）和营销转场（划重点、家人们、看到最后有惊喜）不过。

## 材料

读他指明的 `💡 Ideas/` 和 Fact。Fact 没有默认目录，不猜路径，不新建目录。不打开 Journal 摘句。不扫私人目录来补材料。

核心表达必须是他确认过的那一句 `expression`：Idea 里他确认的整句，或讨论里他确认的整句。中心思想由这一句写成一句读者读完能复述的话，经方向卡他确认；expression 本身不改。不另写一句未经确认的中心思想。测试改写、未确认的 `suggested_expression`、未经他在方向卡确认的模型自拟的 paraphrase，都不能写入 `expression`，不能当中心思想，也不能当成我们的看法。不得把 Idea 收成原话没有的机制名当中心思想。中心思想还没确认，或看法还没确认，就停在选题，不写正文。

## 六步

每周约 2 个 topic。候选可以更多，给他换。他只要 1 条，或这周没有能公开的材料，就按实际条数交，不编一条凑数。不全量塞「评论过的话题」。

要他拍板的有四处：做哪一条、方向卡（中心思想＋论据＋开场场景）、短清单、这一版批不批。方向卡不问素材能否公开。成稿交到审核发布时，正文用到的第一手素材按短清单问；不回，就保持不公开。不必六步各批一次。

他中途来问，就从已经做到的那一步接上。周日 20:00 前，编辑已经确认、自检也通过的，才交出发布包。周一 10:00 把同一张审批卡交给他。编辑还没确认，或自检没过，不要为了赶点交卡。本技能不建定时任务。

### 1. 发现选题

从 Ideas、他指明的 Fact，以及已经确认的经历里，提少量候选。不要把他评论过的话题全部放进候选。

每条先写这篇要表达的一句，再写读者处境、受众问题、缺什么材料。角度不在这一步定死：expression 确认后按生成流程出候选，作者按四测取最高分，不把确认句当成唯一切入。已经确认的 `expression`，写成中心思想一句，经方向卡他确认；expression 本身不改。还没确认的，包括测试改写和 `suggested_expression`，标成待确认，停在选题，不写正文。禁止用 RCT、方法名或期刊名当候选标题。禁止把 Idea 收成新机制名再写成这一句。X 上的热门只能另起一行写成「参考」。参考不是他的观点，也不拿来淘汰他的材料。一条热门下面没有他的观点，就不跟那条热门做题。

这一步的产物是候选选题。`origin` 为 `ai_extension`，除非题目是他先提出来的。

### 2. 确定选题

他选择、改写，或接受某条推荐。接受推荐不等于确认一句模型改写。产物要写明目标、受众、核心表达、我们的看法、写法。核心表达必须是他已确认的 `expression`。标题只放一个主张，带上对象、数字或结果之一。抽象金句不能当标题。

写法只有两种。评新闻是一条直接支撑中心思想的事实，加上已确认的看法。讲观念是一个概念加上至少 1 个具体案例，可以没有外部 Fact。

中心思想或看法还没确认，就停在选题，不写正文。

### 3. 内容策划

写 brief：结构、引用哪条 Idea、引用哪条直接支撑中心思想的 Fact（讲观念没有外部 Fact 就写明不引）、用哪个具体案例（场景、数字或改前改后；第一手优先，外部案例写出处）、哪种写法、排在哪一次。产物是这份 brief。靠假设或外推才接得上的材料不写进 brief。brief 最后一项是方向卡（中心思想＋论据＋开场场景，按生成流程第 4 步）。他确认后，brief 开头补上「方向确认」一节，再写段落因果链（生成流程第 5 步）。

缺材料，或立场和已确认的表达对不上时，一次只问一个问题。可以问：不认同的是结论还是条件；有没有经历过相反的情况；这件事会不会改变做法。他补上的话按确认句记，不把 Journal 原句抄进 brief。反例用来分清真分歧和措辞。讲观念没有第一手具体案例，也没有可查证的外部案例，就退回 intake 补料，不开写。没有确认过的看法，就不写正文。

### 4. 内容生产

### 6. 反馈复盘
