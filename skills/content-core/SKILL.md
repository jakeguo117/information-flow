# content-core

本技能是唯一的 content foundation：意识形态，以及 Idea 到内容的表达底线。不写某一平台的版式。

X 的写法在 `skills/content-x/SKILL.md`。小红书在 `skills/content-xhs/SKILL.md`。公众号在 `skills/content-wechat/SKILL.md`。平台技能只叠渠道写法。旧 `skills/content/SKILL.md` 已停用，不能用它生产正文。

字段、枚举、发布包、正文指纹和批准形状见 `skills/content/references/content-record.md`。`schema_version` 字面量是 `content-0.1`。时区 Asia/Hong_Kong，与上海时间同一钟面。

## 何时加载

他说「做内容」「选题」「写帖」「发布包」或 `/content`，以及内容写手出这一周的草稿：先加载本技能。生成任何封面、配图、插图、卡片或版式之前，必须先加载并遵守 `skills/canvas-design/SKILL.md`，然后加载三个平台技能，一次交齐三版。不出图的草稿可以在本技能之后直接加载平台技能；一旦出图，必须先补上 canvas-design，再出图。

加载顺序：content-core → canvas-design（任何出图之前）→ 平台技能。

canvas-design 是出图用的审美层，不是第四个内容主技能。它没有中文字体，没有 5:2、3:4、21:9，也不产公众号 HTML。这三处只在平台技能里做薄适配，不把平台技能加厚成另一套主技能。

只出某一个平台的样例时，仍先加载本技能；出图前加载 canvas-design；再只加载那个平台技能。样例只按该平台技能写，不用别的平台稿改写充数。

本技能加载的就是这套 foundation。三版和单平台样例都先过下一节「foundation 硬规则」和「写手五条」，再按平台技能写版式。

普通聊天不选题、不出稿。

## foundation 硬规则

写任何一版之前先过这四条。缺一条，不得交卡。配图张数和渠道版式仍在对应的平台技能，这里不复述。出图审美在 canvas-design，不在这里复述。

### 1. anti-AI-slop（全平台）

禁止模板腔、空转句、overrated 或万能开场，包括「清楚过几天就糊了」这一类，以及正确的废话起势。

开门见山，直接说事儿。

长文要有 deeper thought：推论写清假设，机制说透。口语、像真人说话仍要。仅口语不过关。深度和去 slop 是底线。

### 2. X

配图保留 1–3 张，服务逻辑链。Articles 全宽真图等版式仍在 content-x。

行文必须更深、更少 slop。仅「口语自然」不过关。

### 3. 小红书

必须有 visual aid / explanation：解释性配图或图示，类似 X 那种服务逻辑链的说明图。

禁止只靠纯字卡或纯文字卡片交差。

### 4. 公众号

禁止「清楚过几天就糊了」及同类 AI 或 overrated 起势。

开门见山。第一段就直接说事儿：读者处境或判断。论文、RCT 和期刊名不放在第一句。

## 一次交齐

同一 topic 一次生成 X、小红书、公众号三版，放在同一张审批卡上。三版分别按各自平台技能写。本技能不生产正文。

缺任一版，不得交卡。

## 禁止 Journal 原话

不得把周记或私人日记里的句子原话写进 post。标题、摘要、caption、卡片和正文都算。

「周记里已经写清的句子直接引用」已废止。

可以写进稿的是已经 generate、改写过的 Idea，或讨论里确认过的句子。Idea 文本本身也不整段粘贴 Journal。

出处指向 Idea id 或讨论确认句。记录里的 `journal:` 只作出处指针，不把那段原文当正文。

评新闻和讲观念交卡时都用「逻辑链」一节的那条链。正文骨架用「写手五条」，不把这条链印成目录。讲观念的经历必须是改写后的叙述（来自 Idea 或讨论），不是 Journal 粘贴。

交卡前做撞车检查：把三版全部公开文字与可用的 Journal 对照。去掉空白后，仍有连续 20 个字符相同，即红，不得交。

## 深度

配图说明、卡片文案和正文阐释须达到专业自媒体 / essay 编辑水准。

禁止看图写话、标签堆砌、正确的废话、无推论的罗列、「因为所以」断层，以及 shallow、rocky、小学生说明文。

同时过 foundation 硬规则的 anti-AI-slop。长文要有 deeper thought：推论写清假设，机制说透。口语、像真人说话仍要。仅口语不过关。

交稿前强制做一轮 copy-edit 自检。指引是 [autopunk copy-editor](https://github.com/ur-grue/autopunk-media-skills/blob/main/skills/editing/copy-editor/SKILL.md)（只作指引，不把外部仓库拷进本库）：收紧散文，标出逻辑缺口，不偷偷改他已确认的论点。缺口未补，不得交。

## 逻辑链

每篇正文必须能画出这条链。缺环不交。

```
Fact（可核验：链接 + 日期）
  → 推论（为何由此能推出下一步；写明假设）
  → 机制 / 中间含义
  → 结论（对读者意味着什么）
```

不是「事实加感想」两段拼盘。感想必须挂在推论上。

这四行只写在审批卡上，用来看见缺环。不要把 Fact、推论、机制、结论写成正文的小标题或 H2。禁止用 01、02、03 这类编号章节当全文骨架。读者看到的推进是下一节的叙事链。

公众号可以按同一条论证写得更长，不另加他没确认的观点。X 的字数见 content-x。公众号可选的五层加厚见 content-wechat，那是内部对齐，不是读者目录。逻辑链是交卡底线。

交卡时用四行写出这条链，让缺环看得见。

## 写手五条

读者看到的全文按这五条写。审批卡上的 Fact → 推论 → 机制 → 结论仍要能画出来，只是不印成目录。

对照：处境负责对号入座。误判写读者以为对、其实错在哪；Fact 和推论（含假设）放在对号入座之后，用来支撑这个误判。叙事链里的机制对上逻辑链的机制。最小动作是读者今天能做的一步，编号清单只放这里。边界写这条结论在哪停，对上逻辑链的结论，用清晰结论句，不用口号。

五条都要能自检。有一条不过，不得交卡。

1. 选题先写读者处境一句。禁止用 RCT、方法名或期刊名开题。
   自检：候选和标题的第一句是读者此刻的处境。出现 RCT、方法名或期刊名当入口，即不过。
2. 标题至少一个可感知具体（数字、时长、人物或失败场景）。抽象金句不当标题。
   自检：标题里能指出那个具体是什么。只剩一句抽象判断，即不过。
3. 全文骨架是「处境 → 误判 → 机制 → 最小动作 → 边界」。1234 编号清单只许出现在「最小动作」内部。
   自检：正文能按这五步指认。编号清单出现在最小动作之外，或用 01/02/03 当全文骨架，即不过。
4. 开头不超过 3 句完成对号入座。数据和论文放在对号入座之后。
   自检：前三句里有读者熟悉的失败画面或反问。第一句是论文、期刊、样本量或百分比，即不过。
5. 学：收藏型承诺、反转冲突、可带走物。不学：消灭90%、效率翻倍、FOMO 恐吓、空悬念、学术名词当钩子。
   自检：标题或开头能对上「以后用得上」「反转」「拿走的步骤或避坑」至少一种。出现不可核验的夸张收益、恐吓式落后、没有下文的悬念，或用学术名词当钩子，即不过。

同 topic 三版只改入口句，不改核心论点。禁止三版共用同一个学术标题。平台差别是长度和入口，不是深度开关。

- X：首句是痛点或结果预告，接着给可带走的物（步骤、模板、合集或指令）。小标题可裁切，不用 01/02。问句或反转可以，不堆方法名。
- 小红书：人群或结果，加上短时限或避坑。封面第一行要对号入座。入口词用读者会搜的口语。正文前两行给结论或承诺。页与页是因果或时间。结尾指向收藏。
- 公众号：个人经历或判断，标题大约 20–28 字，仍然禁止方法名开场。摘要承接处境。第一段直接说事儿。结尾回收开头的问题，并给出可执行的标准。

反常识可以写。正文前一两屏必须兑现。标题承诺颠覆、正文只复述定义，不过。

节奏：结论段短，解释段可以长。禁止连续五段同一套「主题句加子弹」。转场写判断句，不写「接下来介绍第二节」。结尾给最小下一步，或写明边界。合集可以分块。不是合集，不要用一、二、三、四当全文骨架。假留白（整页金句、空洞反问）和营销转场（划重点、家人们、看到最后有惊喜）不过。

## 排版

段落短，空行分明。小标题有信息量，是判断句，口语清晰，不学术堆砌，也不用小学生标题。不要把 Fact、推论、机制、结论或 01、02、03 当小标题。数据或要点用列表或卡片，不靠一大段糊墙；编号列表只出现在写手五条的「最小动作」里。引文和出处格式统一，用 blockquote 或文末出处块。

结论段短，解释段可以长。转场写判断，不写章节预告。

小红书卡片的纸纹、衬线和页码见 content-xhs。卡片文案是这条逻辑链的压缩版，不是另写浅白口号。分页顺序按写手五条，不把四行逻辑链印成四页标题。

交卡前附排版自检，逐项勾选：

- [ ] 段落短，段间有空行
- [ ] 小标题有信息量，是判断句，不是 Fact / 推论 / 机制 / 结论，也不是 01 / 02 / 03
- [ ] 数据或要点在列表或卡片里，不糊在长段里；编号清单只在最小动作内部
- [ ] 引文和出处格式统一
- [ ] 结论段短、解释段可以长；没有连续五段同一套「主题句加子弹」
- [ ] 转场是判断句，不是章节预告
- [ ] 三版都过了上面各项

## 敏感五类与短清单

这五类保持不公开：家人、钱和持仓、健康、工作客户、具体人名。工作客户含保险。钱和持仓含交易细节。新闻帖只谈观点，不提持仓和交易。

三层过滤决定 `visibility`，不代替发布授权。`public-ok` 只表示这句话可以出现在公开稿里。

1. 自动标记。默认 `private-jake`。上面五类不能写成 `public-ok`。纯观点、原则、行业事实可以放进短清单建议公开。
2. 短清单。只列建议公开的条目，每条是编号加一句话，和审批卡放在同一处交给他。他按「1、3 可以，2 不要」这种回复。只有他回复「可以」的条目进公开稿。不回，就保持不公开。
3. 发卡前再查一遍。只用第二层通过的材料。无持仓和交易，无家人、健康、客户、人名。新闻帖只谈观点。中文。无付费图片工具。这一层对应当前 revision。正文或图片一改，就要重查。

`visibility` 与 ideas 相同：`private-jake`｜`team`｜`public-ok`。省略时是 `private-jake`。

## 不读、不代发、语言

不读 X 收藏夹，不读持仓和交易。

不代发。不登录 X、小红书、公众号，不调用发帖接口。批准表示这一版可以由他本人去发。

语言用中文。

禁止营销腔、标题党、硬金句口号。收束用清晰结论句。

## 图源

生成任何封面、配图、插图、卡片或版式之前，必须先加载并遵守 `skills/canvas-design/SKILL.md`：先写视觉哲学，再落成 PNG 或 PDF。哲学是出图底稿，不写进公开正文。画幅、中文字体、安全区，以及画面、背景、字体是否协调，见平台技能。背景不必是蓝。

优先用 Grok Bot 按本篇论点生成的定制图。

自家数据图、表，以及它们的截图，可以使用，并写出处和日期。

未授权的网页图片不得当作新闻现场照片。评新闻要的可核验图表，用自家数据图或表，或用 Grok Bot 按论点做的示意图，并写出处。

生成图若看起来像实拍新闻，正文标明「配图/示意」。

讲观念可以用生成图，图里没有真人。不用付费图片工具。交实际图片，不只写配图说明。图片和发布包放在同一个 Drive 文件夹，卡上附链接。

换图也要把 revision 加一。图片字节不进 `body_sha256`。

各平台配几张图，见该平台技能。图从哪来，以本节为准。

## 材料

读他指明的 `💡 Ideas/` 和 Fact。Fact 没有默认目录，不猜路径，不新建目录。不打开 Journal 摘句。不扫私人目录来补材料。

核心表达必须是他确认过的那一句（Idea，或讨论里确认的整句）。模型补的句子放在 `suggested_expression`，不能写入 `expression`。这句还没确认，就停在选题，不写正文。

不编造他的观点或经历。AI 的推演保持为建议，不写进他的口气。

## 六步

每周约 2 个 topic。候选可以更多，给他换。他只要 1 条，或这周没有能公开的材料，就按实际条数交，不编一条凑数。不全量塞「评论过的话题」。

要他拍板的只有三处：短清单里哪些可以公开、做哪一条、这一版批不批。不必六步各批一次。

他中途来问，就从已经做到的那一步接上。周日 20:00 前交出已经通过自检的发布包。周一 10:00 把同一张审批卡交给他。自检没过，不要为了赶点交卡。本技能不建定时任务。

### 1. 发现选题

从 Ideas、他指明的 Fact，以及已经改写的经历里，提少量候选。不要把他评论过的话题全部放进候选。

每条先写读者此刻的一句处境，再写受众问题、角度、缺什么材料。禁止用 RCT、方法名或期刊名当候选标题。X 上的热门只能另起一行写成「参考」。参考不是他的观点，也不拿来淘汰他的材料。一条热门下面没有他的观点，就不跟那条热门做题。

这一步的产物是候选选题。`origin` 为 `ai_extension`，除非题目是他先提出来的。

### 2. 确定选题

他选择、改写，或接受某条推荐。产物要写明目标、受众、核心表达、写法。标题至少有一个可感知的具体：数字、时长、人物或失败场景。抽象金句不能当标题。

写法只有两种。评新闻是一条事实加上他的观点。讲观念是一个概念加上改写后的经历。

核心表达还没确认，就停在选题，不写三版正文。

### 3. 内容策划

写 brief：结构、引用哪条 Idea 或 Fact、用哪个案例、哪种写法、排在哪一次。产物是这份 brief。

缺材料，或立场和已确认的表达对不上时，一次只问一个问题。可以问：不认同的是结论还是条件；有没有经历过相反的情况；这件事会不会改变做法。他补上的话按确认句记，不把 Journal 原句抄进 brief。反例用来分清真分歧和措辞。没有改写后的经历，就不写讲观念。

### 4. 内容生产

核心表达已经确认，brief 里点名的缺口也补上之后，才写正文。

按 `skills/content-x/SKILL.md`、`skills/content-xhs/SKILL.md`、`skills/content-wechat/SKILL.md` 各写一版，并过 foundation 硬规则和写手五条。生成封面、配图或卡片前先加载 canvas-design。一次交齐。缺一版，不得进入审核。

### 5. 审核发布

先做三层过滤、foundation 硬规则、交卡逻辑链四行、写手五条、Journal 连续 20 字撞车、copy-edit 和排版自检。出过图的，还要核 canvas-design 已加载，以及画面、背景、字体协调。通过之后，按 `skills/content/references/content-record.md` 的发布包交卡。一张卡一条内容，卡上同时有这三版。

交给他时请他回「收到」。当天没有，再提一次。还是没有，就说明他还没回「收到」。正式副本在 Google Drive「内容/草稿/{年-W周}/」（写成 ISO 周，例如 `2026-W42`）。不把发布包写到这台机器的本地磁盘。

他回「批 / 改 / 不要」。「批」只覆盖卡上写明的那一版。「改」按他的原话改，revision 加一，重新给卡。「不要」这条停止，不再出稿。

bot 不代发。

### 6. 反馈复盘

他亲自发完，并且口头确认发过之后，才把发布结果记成已发布。没有这句确认，就保持未确认。

发后约第 7 天，他若贴来数据和评论，整理进这条的复盘。他可以补咨询、客户或线下听到的反馈。客户和人名若属于敏感五类，只留在未公开的复盘里，不写进公开稿。两周后的按时率、批准率和改动次数由他或 CoS 看。本技能不拉平台数据。流量高低不改 Belief。不写 Cognition。复盘里新的问题可以交给 ideas，本技能不写 Idea 文件。

## 发布授权绑定版本

不把发布包写到这台机器的本地磁盘，不在本机新建内容目录。正式副本在 Google Drive「内容/草稿/{年-W周}/」。`{年-W周}` 写成 ISO 周，例如 `2026-W42`。对话里交的是同一份。

实际的卡片图和封面图与发布包放在同一个 Drive 文件夹。换图也要把 revision 加一。

「批」只覆盖发布包上的 `content_id`、`revision`、`body_sha256`，以及卡上的渠道 `x`、`xiaohongshu`、`wechat_mp`。他若只点名其中的渠道，就只覆盖点名的那些。

标题、摘要、短文案、卡片或任一段渠道正文有实质改动，revision 加一，并重算 `body_sha256`。图片不进 `body_sha256`。只改核心表达或 brief 时，revision 也加一。旧的批对不上当前 revision 或指纹，就不再覆盖，要重新给卡。

批过也不代发。他确认自己发过之后，才记已发布。已批准和已发布是两件事。字段细节以 content-record 为准。

## 自检清单

交卡前逐项写明过或不过。有一项不过，这张卡就不能交给他批。

- [ ] 三版在同一张卡上一次交齐，并分别按 content-x、content-xhs、content-wechat 写成
- [ ] 逻辑链四行完整并写在卡上：Fact（链接和日期）→ 推论（含假设）→ 机制 → 结论；这四行没有做成正文目录
- [ ] 选题先有一句读者处境；开题没有 RCT、方法名、期刊名
- [ ] 标题至少有一个可感知具体（数字、时长、人物或失败场景）；没有用抽象金句当标题
- [ ] 读者向骨架是处境 → 误判 → 机制 → 最小动作 → 边界；1234 编号清单只出现在「最小动作」内部；没有用 01/02/03 当全文骨架
- [ ] 开头不超过 3 句就完成对号入座；数据和论文在这之后
- [ ] 学了收藏型承诺、反转冲突或可带走物；没有消灭90%、效率翻倍、FOMO 恐吓、空悬念，也没有用学术名词当钩子
- [ ] 出任何封面、配图、插图或卡片之前已加载并遵守 canvas-design
- [ ] 三版的画面、背景、字体协调（背景不必是蓝）；画幅、CJK 回退和安全区按各平台薄适配
- [ ] anti-AI-slop（全平台）：没有模板腔、空转句、overrated 或万能开场（含「清楚过几天就糊了」一类）；开门见山，直接说事儿；长文有 deeper thought（推论写明假设，机制说透），仅口语不过
- [ ] X：1–3 张服务逻辑链的配图仍在（版式按 content-x）；行文更深、更少 slop，仅「口语自然」不过
- [ ] 小红书有 visual aid / explanation（解释性配图或图示）；不是纯字卡，也不是纯文字卡片
- [ ] 公众号第一段直接说事儿；没有「清楚过几天就糊了」及同类 AI 或 overrated 起势
- [ ] copy-edit 已做，标出的缺口已补，没有改掉已确认的论点
- [ ] 排版自检已逐项勾选
- [ ] Journal 连续 20 字撞车检查已做，无红
- [ ] 只用了第二层他点过可以、且不属于敏感五类的材料
- [ ] 观点和经历来自 Idea 或讨论确认的改写，没有编造，没有 Journal 原话
- [ ] 图源符合本节「图源」；讲观念的图里没有真人；实际图片已交
- [ ] X 长文符合 content-x（中文，800–1500 字）

## 不要做

- 不代他发帖，不代登录，不把发布包说成已经发出
- 不把候选或模型补的句子写成他的观点，不编造经历
- 不把周记或日记原话写进公开稿
- 不写 `📝 Journal/`、`💡 Ideas/`、Fact 文件、`📖 Cognition/`、`📋 Digests/`
- 不把流量写成某条 Belief 已被证实
- 不读 X 收藏夹、持仓、交易
- 不新建定时任务，不改 workflow
- 不把未授权网图当成新闻现场照
- 不在未加载 canvas-design 时出封面、配图、插图或卡片
- 不把 Fact、推论、机制、结论或 01/02/03 写成全文目录
- 不用 RCT、方法名、期刊名开题，不用抽象金句当标题
- 不落盘：不把发布包写到这台机器的本地磁盘，不在本机新建内容目录
