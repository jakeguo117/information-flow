# content

给 Jake 自己用。字段、枚举和发布包整页见 `references/content-record.md`。`schema_version` 字面量是 `content-0.1`。时区 Asia/Hong_Kong，与上海时间同一钟面。

规则源在 information-flow。六步来自 V2.0 Draft「03_表达挖掘与内容运营」（file id `1kfrSUQu5u1eR2avFDZ9qJeI4xaPuai5xsrwiqTRPfKs`）§3。记录字段对照同目录 Draft「02_数据规则与开发验收」（file id `11gFwzKUxHsQ5_KSk3NFXcM_5vaB-QbJwrq5hk71XBIQ`）里 Content 那一句，以及通用字段。两份都还是 Draft。本包只定 content-0.1 的流程和记录形状。

本包不改 DigitalBrain 里已有的笔记。不落盘是指不把发布包写到这台机器的本地磁盘。发布包的正式副本在 Google Drive「内容/草稿/{周}/」，`{周}` 写成 ISO 周，例如 `2026-W42`。对话里给的是同一份，由他本人发出。

## 什么时候用

- 他说「做内容」「选题」「写帖」「发布包」或 `/content`
- 内容写手要出这一周的草稿

普通聊天不选题、不出稿。

表达按这个单元展开：触发点和来源，他的反应，为什么这样想，亲身经历或依据，想让读者带走什么。反应可以是疑问、反对、有条件的认同、判断改变或做法。AI 提的角度标成建议。

## 读什么

Vault 按这个顺序认，认到就停：

1. `$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/DigitalBrain` 若存在且有 `📝 Journal/`
2. 当前工作区根目录，若有 `📝 Journal/`
3. 否则停下来问他，不要猜路径

只读 `💡 Ideas/`、`📝 Journal/`，以及他指明的 Fact 节点。Fact 没有默认目录，不猜路径，不新建目录。周记里已经写清的句子直接引用，不必再问一遍。不扫私人目录来补材料。

## 六步

每周 2 条。候选可以多于 2 条，给他换。他只要 1 条，或这周没有能公开的材料，就按实际条数交，不编一条凑数。

他中途来问，就从已经做到的那一步接上。周日 20:00 前交出已经通过自检的发布包。周一 10:00 把同一张审批卡交给他。自检没过，不要为了赶点交卡。本技能不建定时任务。

要他拍板的只有三处：短清单里哪些可以公开、做哪一条、这一版批不批。不必六步各批一次。

### 1. 发现选题

从 Ideas、Journal、Facts，以及他已经讲过的经历里，提少量候选。不要把他评论过的话题全部放进候选。

每条写清受众问题、角度、缺什么材料。X 上的热门只能另起一行写成「参考」。参考不是他的观点，也不拿来淘汰他的材料。一条热门下面没有他的观点，就不跟那条热门做题。

这一步的产物是候选选题。`origin` 为 `ai_extension`，除非题目是他先提出来的。

### 2. 确定选题

他选择、改写，或接受某条推荐。产物要写明目标、受众、核心表达、写法。

写法只有两种。评新闻是一条事实加上他的观点。讲观念是一个概念加上他的亲身经历。

核心表达必须是他的原话，或他确认后的那一整句。模型补的句子放在 `suggested_expression`，不能写入 `expression`。这句还没确认，就停在选题，不写三版正文。

### 3. 内容策划

写 brief：结构、引用哪条 Idea 或 Fact、用哪个案例、哪种写法、排在哪一次。产物是这份 brief。

缺经历，或立场和他的原话对不上时，一次只问一个问题。可以问：不认同的是结论还是条件；有没有经历过相反的情况；这件事会不会改变做法。他补上的话按原话记。反例用来分清真分歧和措辞。没有他的经历，就不写讲观念。

### 4. 内容生产

核心表达已经确认，brief 里点名的缺口也补上之后，才写正文。不编造他的观点或经历。AI 的推演保持为建议，不写进他的口气。

一条帖子出三版，放在同一张卡上：

- X 长文：中文，800–1500 字，分段清楚。
- 小红书：一句短文案，加上图片卡片的文案，以及做好的卡片图。卡片用纸纹底、衬线字、小标题、页码 n/N，封面可以用竖排标题。背景、颜色、字体可以变，封面也可以变。
- 公众号：和这篇 X 长文说的是同一件事，不另加他没说过的话。标题、摘要、实际封面图和封面说明、小标题分段、放在正文里的实际图片、文末出处，都要有。

评新闻的配图用真实图表或截图，并注明出处。讲观念可以用生成图，图里没有真人。不用付费图片工具。内容写手交文案，并交出实际的卡片图和封面图，不只写配图说明。卡片图和封面图与发布包放在同一个 Drive 文件夹，卡上附链接。

事实写上来源链接和日期。不读 X 收藏夹，不读持仓和交易。新闻帖只谈观点。

### 5. 审核发布

先做下面的三层过滤和自检。通过之后，按 `references/content-record.md` 的发布包交卡。一张卡一条帖子，卡上同时有这三版。

交给他时请他回「收到」。当天没有，再提一次。还是没有，就说明他还没回「收到」；这张卡的正式副本在 Google Drive「内容/草稿/{周}/」，不在这台机器的本地磁盘上。

他回「批 / 改 / 不要」。「批」只覆盖卡上写明的那一版。「改」按他的原话改，revision 加一，重新给卡。「不要」这条停止，不再出稿。

bot 不代发。不登录 X、小红书、公众号，不调用发帖接口。批准表示这一版可以由他本人去发。

### 6. 反馈复盘

他亲自发完，并且口头确认发过之后，才把发布结果记成已发布。没有这句确认，就保持未确认。

发后约第 7 天，他若贴来数据和评论，整理进这条的复盘。他可以补咨询、客户或线下听到的反馈。两周后的按时率、批准率和改动次数由他或 CoS 看。本技能不拉平台数据。流量高低不改 Belief。不写 Cognition。复盘里新的问题可以交给 ideas，本技能不写 Idea 文件。

## 三层过滤

这三层决定 `visibility`，不代替发布授权。`public-ok` 只表示这句话可以出现在公开稿里。

1. 自动标记。默认 `private-jake`。家人、钱和持仓、健康、工作客户、具体人名，这五类保持不公开，不能写成 `public-ok`。纯观点、原则、行业事实可以放进短清单建议公开。
2. 短清单。只列建议公开的条目，每条是编号加一句话，和审批卡放在同一处交给他。他按「1、3 可以，2 不要」这种回复。点名可以的条目才进公开稿。不回，就保持不公开。
3. 发卡前再查一遍。只用第二层通过的材料。无持仓和交易，无家人、健康、客户、人名。新闻帖只谈观点。中文。无付费图片工具。这一层对应当前 revision。正文或图片一改，就要重查。

`visibility` 与 ideas 相同：`private-jake`｜`team`｜`public-ok`。省略时是 `private-jake`。

## 自检清单

交卡前逐项写明过或不过。有一项不过，这张卡就不能交给他批。

- [ ] 只用了第二层他点过可以、且不属于敏感五类的材料
- [ ] 观点和经历来自他的原话或他确认过的表达，没有编造
- [ ] 事实有来源链接和日期；评新闻的配图注明出处；讲观念的图里没有真人
- [ ] X 长文 800–1500 字，分段清楚
- [ ] 公众号版和这篇 X 长文一致，没有另加他没说过的话；标题、摘要、实际封面图、小标题、正文里的实际图片、文末出处都在；小红书的实际卡片图也在
- [ ] 没有持仓、交易、家人、健康、工作客户、具体人名
- [ ] 中文；没有用付费图片工具；没有用 X 收藏夹里的内容
- [ ] 三版在同一张卡上；若卡上已写批准，批准绑的是这一版的 revision 和 body_sha256

## 发布授权绑定版本

「批」只覆盖发布包上的 `content_id`、`revision`、`body_sha256`，以及卡上的渠道 `x`、`xiaohongshu`、`wechat_mp`。他若只点名其中的渠道，就只覆盖点名的那些。

标题、摘要、短文案、卡片或任一段渠道正文有实质改动，revision 加一，并重算 `body_sha256`。图片不进 `body_sha256`，换了卡片图、封面图或正文里的图片，换图也要把 revision 加一，旧的批不覆盖换过图的稿。只改核心表达或 brief 时，revision 也加一。旧的批对不上当前 revision 或指纹，就不再覆盖，要重新给卡。

批过也不代发。他确认自己发过之后，才记已发布。已批准和已发布是两件事。

## 不要做

- 不代他发帖，不代登录，不把发布包说成已经发出
- 不把候选或模型补的句子写成他的观点，不编造经历
- 不写 `📝 Journal/`、`💡 Ideas/`、Fact 文件、`📖 Cognition/`、`📋 Digests/`
- 不把流量写成某条 Belief 已被证实
- 不读 X 收藏夹、持仓、交易
- 不新建定时任务，不改 workflow
- 不落盘：不把发布包写到这台机器的本地磁盘，不在本机新建内容目录。发布包的正式副本在 Google Drive「内容/草稿/{周}/」
