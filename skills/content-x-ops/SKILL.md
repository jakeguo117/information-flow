# content-x-ops

由 X 运营加载。不写 X 长文母稿。母稿由内容写手加载 content-core → content-x 来写。本岗做发帖、引用再分发、复活计划、渠道落版（封面／标题／引子叠不叠字）。与写母稿分线程，一次只做一类。不加载 content-xhs 或 content-wechat。

谁干什么：写手＝选题②＋包装 brief①＋basement／母稿＋CTA 文案③；视觉＝出图；渠道运营＝落版／叠字／发帖；冷读＝内容审计。

五条全开启用（Jake 2026-10-22 22:33）。不是 C 案的首期裁剪。五节都实操。预告和拆串的跟发步骤在「网页跟发」。

Jake 2026-10-29：预告和拆串不交清单等手点，长文代发成功后走已登录的 X 网页跟发。引用再分发、沉睡账号 Article 复活仍只出清单。这几节都不写正文。

## 边界

- 只读发布包。发布包路径见 `skills/content/references/content-record.md`。跟发不改发布包。
- 清单、填好的槽位、跟发回执、兜底清单写到 `内容/X运营/`。不写回写手草稿目录，不写进本仓库。
- 不发明求互动话术。与 content-x 的收束、以及下面 OCR 的禁求互动一致。槽位和待发正文里不得出现求回复、求转发、求分享、求点赞。
- 一次一类流程。网页跟发只跑预告短帖和拆串这一类。不把写长文、引用再分发、复活计划混进同一趟。
- 不写正文。①包装走 content-x-article-packaging，②选题走 content-x-process-topic，③CTA 走 content-x-cta-loop。跟发只粘贴已有原句，不改写、不摘要、不现拆。
- 长文本身由现行代发完成。本技能不重发长文，也不把「已批」「草稿已建」「预览截图」当成已发出。
- 跑网页跟发时以本节为准。写手和 bot 仍不代发，见 content-core。本技能不改 content-core。置顶、引用再分发、早回复、订阅仍只出清单，不在这次跟发里点。
- 短帖没有可代发的接口可用：user-X 有 `article_create_draft`，没有短帖 create_post；内置 x 只读。预告和拆串只能在已登录的 X 网页发。`article_create_draft` 不用于预告或拆串。API 短帖另议，本版不走。
- 不代发小红书。不登录小红书。
- 不开未批 cron，不写定时扫描。事件驱动：长文成功回执到手，X 运营当即跑这一趟。
- 日常跟发归 X 运营。Eng 不建、不值守日常发帖机器人。本技能和槽位模板只规定这一趟怎么做。

## 发前预告与置顶

**启用（全开）。**

预告短帖不在发前交清单手点。长文代发成功、回执到手之后，有预告成稿才按「网页跟发」发。审过但长文未公开，不发预告。

新文置顶 24–72 小时仍只出清单，不在网页跟发里点置顶。

## 长文拆串

**启用（全开）。**

长文代发成功之后，有拆串成稿才按「网页跟发」发成串。末条回链全文。没有成稿不现拆、不代写。

## 网页跟发：预告短帖与拆串

长文成功后的准自动跟发。以前只出清单，交 Jake 手点。现在回执一到，X 运营在已登录网页按槽位贴文、点一次发、抓链接。清单只在缺稿或失败时写兜底。不是无人值守的接口机器人。登录、验证码或风控挡住就停，交给人工。

### 触发

两样都在才开始。少一样，整趟不动短帖。

- 长文公开链接：`https://x.com/` 下的状态链接，或已公开的 Articles 阅读链接。
- 长文成功回执：明文写已发出或已公开，并且 content_id、revision 对得上发布包。

只有已批、草稿已建或预览截图：回执写「未触发：长文未公开」。预告栏和拆串栏都写「未触发」。不发预告，不发拆串。

### 成稿

槽位模板在 `skills/content-x-ops/templates/preview-short.md` 和 `skills/content-x-ops/templates/thread.md`。填好的文件放 `内容/X运营/{content_id}-预告.md`、`内容/X运营/{content_id}-拆串.md`。

- 预告成稿：标题、引子两槽都是发布包或包装三件套里的原句，加上这趟的长文公开链接。三槽齐，才算有预告稿。运营不改字。
- 拆串成稿：每一条都是发布包 X 正文或包装三件套里的原句，顺序已经排好。末条是标题原句加长文公开链接。跟发当时不从长文现拆、不摘要。
- 句子在发布包里对不上，或必填槽是空的：这一段算缺稿。

### 链路

1. 核对触发。未触发则停。
2. 有预告成稿，且回执没有「预告漏发」「预告成功」：网页代发预告短帖。
3. 长文已由现行代发公开。本趟不重发长文。
4. 有拆串成稿，且回执没有「拆串：成功」：网页代发拆串。末条回链全文。
5. 同一 content_id＋revision，成功过的那一段不重发。

缺稿就停在那一段，不代写。回执写明缺的是预告、拆串，还是两段都缺。

长文已公开，但预告缺稿，或已有回执写明预告漏发：不补假预告，不新写一条「即将发布」。拆串成稿在，就只跟拆串。

### 网页步骤（预告）

用已登录的 X 网页。浏览器是 box，或运营桌面里已经登录该账号的浏览器。不要换账号，不要开未登录窗口硬发。

- P1. 打开 `https://x.com/compose/post`。
- P2. 页面是登录、验证码、人机验证、锁号、限流，或看不到「发帖」／Post：停在 P2。不要猜别的入口。
- P3. 把预告槽位里的「待发正文」原样贴进输入框。不加词，不加第二链接，不求互动。
- P4. 点一次「发帖」或 Post。新帖出现之前不要再点。
- P5. 打开这条新帖，复制状态链接（`https://x.com/…/status/…`）写入回执。复制不到就停在 P5，不要再点发帖。

### 网页步骤（拆串）

预告缺稿、漏发或不补，不挡住拆串。预告已发出的不删。若预告停在 P2，原因是登录、验证码或风控：拆串不要换入口再试，回执拆串栏写停在 T1，原因与 P2 相同。

- T1. 预告若已因登录、验证码或风控停在 P2：不再打开撰写框，拆串记停在 T1，原因照抄 P2。除此之外，用同一个已登录浏览器打开 `https://x.com/compose/post`。这一步被挡住也停在 T1，不改走别的入口。
- T2. 贴第 1 条。用撰写框的加帖（「+」或「添加帖子」）按槽位顺序加到末条。末条只贴槽位末条，里面必须有长文公开链接。
- T3. 找不到加帖控件：停在 T3。不要改成连续单帖连发。
- T4. 点一次「全部发帖」或 Post all。不要再点。
- T5. 按顺序复制每条状态链接。条数对不上，或末条正文里没有长文链接：停在 T5，把已经看见的链接写上。

### 回执

每一趟结束都写，成功也写。路径：`内容/X运营/{content_id}-跟发回执.md`。

```markdown
# 跟发回执 {content_id} r{revision}

- 触发：已公开 | 未触发：长文未公开
- 长文链接：
- 长文回执：
- 预告：未触发 | 成功 {链接} | 缺稿未发 | 漏发不补 | 已发不重发 | 停在 P{n}（登录|验证码|风控|没有发帖按钮|点了但没有新帖|抓不到链接）
- 拆串：未触发 | 成功 第1条 {链接} … 末条 {链接} | 缺稿未发 | 已发不重发 | 停在 T{n}（登录|验证码|风控|没有加帖|没有全部发帖|条数对不上|末条没有全文链接）
- 未自动重试：是
- 人工下一步：无 | {一句：在已登录网页对哪一段点一次发帖，把链接补进这份回执}
```

停住、缺稿或漏发时，另写 `内容/X运营/{content_id}-跟发兜底.md`。只抄还没发出的待发正文。缺稿就写空槽的名字，不补句子。写上长文链接、卡在 P 几或 T 几、人工点一次之后把链接补回回执。这份清单是兜底，不是这一趟的主路。

不盲重试，不刷量。同一段失败后不改字再发，不自动重开网页连点，不另发一串充数。重发只许人工按兜底清单做一次，并写回同一份回执。

### 验收

一趟算跟完，要同时满足：

- 回执在。触发栏是「已公开」或「未触发：长文未公开」。未触发时，预告和拆串都没有新链接。
- 预告栏是这六类之一：未触发、成功并带状态链接、缺稿未发、漏发不补、已发不重发、停在 P 几并写明挡住原因。
- 拆串栏是这五类之一：未触发、成功并按顺序带每条状态链接且末条正文有长文链接、缺稿未发、已发不重发、停在 T 几并写明挡住原因。
- 停住、缺稿或漏发时，有兜底清单，且清单里没有发布包以外的新句子。
- 「未自动重试」是「是」。人工下一步要么是「无」，要么是一句点哪一段、把链接补回哪份回执。

### 谁跑

改本技能和槽位模板，是技能变更。每天长文回执到手后的跟发，仍由 X 运营加载本技能执行。Eng 不做日常发帖机器人。

## X 长文引用再分发

**启用。** 与「长文拆串」相邻，但是另一条线：拆串在长文代发成功后按「网页跟发」发；本节是长文已经发出之后，用引用转推再推。本节只出清单，不代发，不进网页跟发。

- **触发**：长文发出后阅读低，或有新证据、新粉。
- **做什么**：用引用转推换欲望或异议角度再推。可以配新案例、权威背书，或面向新粉。不改原文，不写新的长文正文。
- **产出**：2–N 条引用 hook，加上排期。清单写到 `内容/X运营/`。
- **验收**：每条 hook 与原文包装三件套不重复卖点。有基线对比（引用前／后阅读）。

直发范围未另定前，清单交 Jake 点发。

## 沉睡账号 Article 复活（约 7–30 天）

**启用。账号非沉睡时，暂不作首期例行复活计划。** 还在发，或刚发过长文、不算沉睡的，不把本节排进首期例行。

- **触发**：长期不发，或每帖极低曝光。账号非沉睡则不开始这份例行计划。
- **做什么**：先定包装，走 content-x-article-packaging，本岗不写三件套。流程长文仍走 content-core + content-x，写手可写 basement，与跑本技能分线程，本岗不写正文。首发之后按「X 长文引用再分发」跑约 7–30 天，盯阅读和每篇新粉。CTA 的去向链接、转化位与写手对齐，文案走 content-x-cta-loop，本岗不写。
- **产出**：复活 30 天计划，加上基线／目标表。清单写到 `内容/X运营/`。
- **验收**：有发布前基线。周期结束有对照。不中途改指标。数字当个案，不照搬外部宣称的倍率。
