# content-x-ops

由 X 运营加载。不写 X 长文母稿。母稿由内容写手加载 content-core → content-x 来写。本岗做发帖、引用再分发的排期与网页代发、复活计划、渠道落版（封面／标题／引子叠不叠字）。引用再分发文案归写手，见 content-x。与写母稿分线程，一次只做一类。不加载 content-xhs 或 content-wechat。

谁干什么：写手＝选题②＋包装 brief①＋basement／母稿＋CTA 文案③；视觉＝出图；渠道运营＝落版／叠字／发帖；冷读＝内容审计。

五条全开启用（Jake 2026-10-22 22:33）。不是 C 案的首期裁剪。五节都实操。步骤细节以后拆。

下面两节：引用再分发（文案在写手成稿包；本岗只排期＋网页代发），以及沉睡账号 Article 复活。五条不动。本岗不写引用文案，也不写长文正文。

## 边界

- 只读发布包。
- 清单写到 `内容/X运营/`。不写回写手草稿目录。
- 不发明求互动话术。与 content-x 的收束、以及下面 OCR 的禁求互动一致。
- 一次一类流程。一次会话只跑一类，避免混上下文。写长文与运营也可以分成两次线程。
- 不写正文。①包装走 content-x-article-packaging，②选题走 content-x-process-topic，③CTA 走 content-x-cta-loop。本岗不写这三条的文案。
- 代发范围以现行职责为准。bot 不代发、不点发布，见 content-core。预告、拆串、置顶只出清单，交 Jake 点发。引用再分发不在此列：不自写 hook，只排期＋网页代发（见下节）。直发范围未另定前不扩大。
- 预告／拆串的全自动发帖是另线。本技能不实现自动发帖。
- 不代发小红书。不登录小红书。

## X 长文引用再分发

**启用。** 与「长文拆串」相邻：拆串是把长文拆成串并回链全文；本节是长文发出之后，用引用转推再推。文案不在本岗写。写手在 content-x 成稿包里交「引用再分发文案组」。本岗只排期＋网页代发。

- **文案**：接写手成稿包。不自写 hook，不重写角度，不重写开头语。缺这组就停，退回写手，不在这里补写主包。
- **做什么**：按文案组的建议日序排期。钟点仍归运营／Jake。在网页引用原文帖，把「引用帖草稿」原文贴上。约 5–7 条，一天一条。不改原文，不写新的长文正文。
- **追加**：阅读异常（阅读低，或有新证据、新粉）时可以追加补发条。追加不挡、不替换写手主包。追加条仍不得与包装三件套撞卖点。
- **语种**：跟该篇要发的 X 长文。英文长文的引用帖用成稿包里的英文草稿。不另做中文引用串。
- **已发不补**：已发出的长文不回头补文案组，含《收藏了不用》。
- **冷读**：短帖已与长文同包轻过（禁编造、禁与包装三件套撞卖点）。本岗不另开长审。
- **产出**：排期，加上网页代发时贴上的写手草稿。清单写到 `内容/X运营/`。本岗不另写短帖正文。
- **验收**：运营没有重写角度或开头语。每条对得上成稿包里的一条草稿。有基线对比（引用前／后阅读）。

bot 不点发布，见 content-core。直发范围未另定前不扩大。预告、拆串、置顶仍只出清单，交 Jake 点发。

## 沉睡账号 Article 复活（约 7–30 天）

**启用。账号非沉睡时，暂不作首期例行复活计划。** 还在发，或刚发过长文、不算沉睡的，不把本节排进首期例行。

- **触发**：长期不发，或每帖极低曝光。账号非沉睡则不开始这份例行计划。
- **做什么**：先定包装，走 content-x-article-packaging，本岗不写三件套。流程长文仍走 content-core + content-x，写手可写 basement，与跑本技能分线程，本岗不写正文。首发之后按「X 长文引用再分发」排期并网页代发，文案用写手成稿包，本岗不另写 hook；阅读异常可追加。周期约 7–30 天，盯阅读和每篇新粉。CTA 的去向链接、转化位与写手对齐，文案走 content-x-cta-loop，本岗不写。
- **产出**：复活 30 天计划，加上基线／目标表。清单写到 `内容/X运营/`。
- **验收**：有发布前基线。周期结束有对照。不中途改指标。数字当个案，不照搬外部宣称的倍率。
