# content-x-cta-loop

CTA 闭环。读完长文的人是 **hyper-warm**：文末必须有自然下一步；无去向＝荒谬（原文口径）。CTA 文案归写手；链接／转化位与 X 运营对齐；发帖归 X 运营。

**谁加载**：内容写手（正文近定稿时）。X 运营不再写母稿，也不写这条 CTA 文案。

**谁干什么**：写手＝选题②＋包装 brief①＋basement／母稿＋CTA 文案③；视觉＝出图；渠道运营＝落版／叠字／发帖；冷读＝内容审计。

**来源**（机制对照，非硬 KPI）：https://x.com/i/article/2100174331804540928 ；镜像 https://haowenji.com/articles/x-2100174331804540928 ；帖 https://x.com/ItsMeBenChan/status/2114698558712774840 。纸面内容侧草案。作者宣称倍率不当 CTA 验收数字。

## 触发

- 长文接近定稿：骨架已过 F（采访／骨架闸），正文近终稿。
- 包装三件套已定或并行收口时，可同链补 CTA，但仍以近定稿为准，避免正文未稳先堆转化话术。

## 输入

- 近终稿正文（或稳定段落因果链）＋文中已承诺的「读者能带走的下一步」。
- 可选下一步类型：系列文链接、lead magnet、newsletter、约 call／高客单入口。
- X 运营提供或待对齐的去向 URL／转化位；没有则产出里标「待对齐」，不编造链接。
- 不输入：求互动话术库、代发授权。引用再分发文案不进本岗：文案＝写手成稿包（content-x）；排期与网页代发＝运营（content-x-ops）。

## 做什么

1. **定自然下一步**（至少一类，与正文承诺一致）：
   - 其他相关 Article／系列下一篇
   - lead magnet
   - newsletter
   - book a call（或团队认可的约谈入口）
2. **温度匹配**：
   - 读完长文＝高意向（hyper-warm）→ 可用更高客单 CTA（约 call／产品），但仍须与文中机制／承诺一致，不硬塞无关售卖。
   - 文中只讲到「可跟做的一步」却未铺垫高客单 → 先用 lead magnet／系列文，不跳变。
3. **写文末 CTA 段**：
   - 位置固定：takeaway →（可选试一句）→ CTA 段 → punchline。punchline 仍是全文最后一句。CTA 段不放到 punchline 后面。
   - 口语、短。不提问求回复、不求转发／分享。
   - 写清读者点下去会得到什么；动作明确（读／领／订／约）。
4. **去向对齐**：
   - URL／转化位与 X 运营对齐后写入定稿。
   - 未确认：正文可留占位并标 **「待对齐」**，交运营回填；不擅自发明短链或未授权页。
5. **禁止求互动**（与 content-x 收束、content-x-ops／OCR 一致）：
   - 不求赞、求转、求评、求回复凑互动。
   - 不把「留言我说」当唯一 CTA。
6. **检查表**：
   - [ ] 文末顺序是 takeaway →（可选试一句）→ CTA 段 → punchline，punchline 仍是全文最后一句
   - [ ] 文末有清晰的自然下一步（可并列，但主动作一个）
   - [ ] 与文中承诺一致，无跳变硬卖
   - [ ] 去向已对齐或已标「待对齐」
   - [ ] 无求赞／求转／求评
   - [ ] 未把宣称倍率写进 CTA 话术当保证

## 产出

- **文末 CTA 段**（可直接贴进 basement 文末）。
- **去向链接**（已确认 URL，或「待对齐」＋拟去向类型）。
- 交接：文案归写手定稿；链接／转化位回 X 运营确认；**发帖归 X 运营，不代发**。成稿冷读交「内容审计」。

## 验收

- 读完有明确动作。
- 与文中承诺一致。
- 无求互动指令。
- 无去向且无「待对齐」标注 → 不合格。

## 边界／不做

- 不代发；不改运营排期／置顶／拆串。
- 不写小红书／公众号 CTA 卡面。
- 封面出图归视觉；本 skill 不出图。
- 不发明 Jake 未说过的优惠／承诺／价格；高客单话术须在已确认表达范围内。
- 禁靠 context 才懂的词。
- 敏感五类／禁 Journal 原话：与 content-core 对齐，引用不复述全文。
- 不写引用再分发文案，也不把引用文案派给运营侧，不写引用 hook。文案＝写手成稿包（content-x）；排期与网页代发＝运营（content-x-ops）。
- 不把作者宣称倍率当转化 KPI。

## 与邻 skill 关系

- **须先或可并行**加载 `content-core`。
- 正文写法另循 `content-x`；禁求互动与 content-x／OCR 一致。
- 加载顺序：选题② → 采访／骨架 → Jake 认可 → 包装① → content-x 正文 → **本 skill**。
- 去向对齐可与 X 运营／content-x-ops 接口，但不加载运营五条来写正文；一次一类或写清顺序。
