# Facts

依据是开工包里已经写明的规则：§1.2（一条 Fact 一个节点、稳定 ID）、§1.3 D3 / D5、§1.4（入库不等于证实）、§5 AC09、§6 T36。开工包没有写的字段和规则，这里不补。

## 节点

一条 Fact 一个节点，用稳定 ID。

## 验证状态

只有四个值：

- 待核验
- 已核验
- 有争议
- 已更正

开工包没有给这四个值的英文枚举名。

入库不等于证实。写入本身不会把状态改成已核验；状态只有调用方明确给出上面四个值之一才成立。

## 历史

历史只追加。改验证状态，或做更正，都是再追加一条新记录。已经写下的记录不改写，也不删除。

开工包没有写：新记录是否覆盖旧记录成为「当前状态」，更正时哪些字段必须变化，以及状态之间的迁移限制。

## 链接和日期

事实带链接和日期（D3，保留）。开工包没有写字段名，也没有写缺了链接或日期时要不要拒绝。

## 公开

默认不公开（D5，保留）。开工包没有写 Fact 的 visibility 取值。

## 周记

一个 Fact 节点可以没有任何周记引用它（AC09）。周记引用不是这条规则里的必填项。

## 检索和引用

`retrieve` 要能按关键词找到这个节点。节点的稳定 ID 要能被内容记录引用（AC09）。开工包没有写内容记录用哪个字段名来引用 Fact。

## 工具暂时用的键

下面这些键名开工包没有规定。`skills/facts/tools/write_fact.py` 为了能写入、校验和检索，暂时用它们。它们不是开工包里的字段规范。

| 键 | 写入时 | 说明 |
|---|---|---|
| `id` | 必填，非空字符串 | 稳定 ID |
| `verification_status` | 必填 | 只能是上面四个值 |
| `text` | 必填，非空字符串 | 关键词在这段文字里找 |
| `link` | 可缺 | 给了就原样放进这一条新记录 |
| `date` | 可缺 | 给了就原样放进这一条新记录，不解释格式 |

一条记录是输出文件里的一行 JSON。同一个 `id` 再写一次，就是追加一行。新行不从旧行抄字段。

调用方用 `--out` 指定目录或文件。不存在的路径当成文件。已经存在的目录则追加到该目录里的 `facts.jsonl`。这个文件名开工包没有规定。
