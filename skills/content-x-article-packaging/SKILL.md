# content-x-article-packaging

包装三件套（Packaging Trifecta）。封面 brief／标题／引子是**一整件产品**，不是三件散件。读者扫视路径：banner 抓眼 → title 勾住 → intro 对齐预期 → 点击进文。

**谁加载**：内容写手（现行：写 X 长文 basement；先 content-core 再 content-x）。可与 content-x 同任务链；一次只做包装，或写清顺序（选题→包装→正文→CTA）。

**来源**（机制对照，非硬 KPI）：Benjamin Chan Article https://x.com/i/article/2100174331804540928 ；镜像 https://haowenji.com/articles/x-2100174331804540928 ；帖 https://x.com/ItsMeBenChan/status/2114698558712774840 。纸面：`纸面-内容侧草案-BenjaminChan-Article复活-20261027.md`。作者宣称阅读倍率等为个案，**不当验收硬数字**。

## 触发

- 要发／改一篇 X Article（长文 basement 开写前，或定稿前的包装闸）。
- 账号复活／冷启动要先定包装再写流程文时，也走本 skill。

## 输入

- 已过流程选题（或本周认可选题卡）：来源资产、中心思想一句、读者是谁。
- 方向卡或 brief 里已有：终版中心思想／主论据／开场场景（若尚未确认，先走 content-core 方向确认，不先硬写包装）。
- 可选：既有热帖／案例一句话，供「卖梦想」或「拆异议」取材。
- 不输入：运营侧引用 hook 排期、出图成品、代发授权。

## 做什么

1. **先定三位置各做一件事**（二选一，且三者不重复卖同一点）：
   - **卖梦想（sell the dream）**：读者想要的结果／状态，具体可感知。
   - **拆异议（answer an objection）**：读者「凭什么信」「这招真的吗」「适不适合我」里的一条。
2. **分配表**（写进产出；可参考原文例，勿照搬数字当承诺）：
   - 封面（Banner）：一句职责＋brief（画面要解决什么异议或梦想；5:2；禁「随便 AI 封面」）。
   - 标题（Title）：一句职责＋定稿标题（具体＋勾好奇＋承诺价值；禁空泛 5 秒标题、百分比钩子）。
   - 引子（Intro／短钩）：一句职责＋定稿文案（对齐点击后预期；不重复标题已卖的点）。
3. **重叠检查**：三人（或自检）能否一眼说出「封面解决 A、标题解决 B、引子解决 C」且 A≠B≠C。同卖一个点 → 重写分配。
4. **闸门**：三者职责或定稿文案任一想不清 → **停写正文**（原文口径：想不出让人点的理由就不写）。回到选题或方向卡，不硬开写。
5. **封面 brief → 内容视觉**：本岗只交 brief（画幅 5:2、要传达的一点、禁忌元素）；出图／裁切归内容视觉（canvas-design + content-visual）。本岗不出图。
6. **定稿前检查表**（全部勾上才放行正文或定稿）：
   - [ ] Banner／Title／Intro 当作一整件产品，不是三件散件
   - [ ] 扫视路径成立：抓眼 → 勾住 → 对齐预期 → 可点击
   - [ ] 每位只做「卖梦想」或「拆异议」之一
   - [ ] 三者不重叠卖同一点
   - [ ] 标题兑现点在正文里找得到（不空头承诺）
   - [ ] 封面 brief 已交视觉；本岗无出图文件冒充交付
   - [ ] 无求赞／求转／求评话术混进引子

## 产出

- **三件套说明**：封面／标题／引子各「一句职责＋定稿文案」（封面为 brief，非成图）。
- **定稿前检查表**（上文勾选项，可贴 brief）。
- 交接：封面 brief → 内容视觉；包装定稿文案进 basement／发布包 X 段字段；**不代发**。

## 验收

- 外人一眼能说清三者各解决什么。
- 无三者同卖一个点。
- 包装不清时正文未开写（或已叫停）。
- 封面只有 brief、无本岗出图。

## 边界／不做

- 封面执行／出图归内容视觉；本岗可写 brief，不出图。
- 不代发；发帖归 X 运营。
- 不写小红书正文／caption／卡面；不写公众号。
- 不发明 Jake 没说过／未确认的观点；不把未确认 paraphrase 当包装承诺。
- 禁靠 context 才懂的词；新概念用读者懂的话。
- 与 content-core：**敏感五类**、**禁 Journal 原话**（连续 20 字撞车）对齐——此处不复述全文，加载 content-core 为准。
- 不做运营侧 ④ 引用再分发、⑤ 沉睡号复活计划（归 X 运营／content-x-ops 邻域）。
- 不把作者宣称倍率（如「70 倍」）写进包装承诺或验收数字。

## 与邻 skill 关系

- **须先或可并行**加载 `content-core`。
- 写正文时另循 `content-x`（版式／写法）；本 skill 不代替 content-x。
- 本三条顺序建议：`content-x-process-topic`（选题）→ 本 skill（包装，可在正文前）→ content-x 正文 → `content-x-cta-loop`（近定稿）。
- 一次只做一类，或在任务里写清顺序；可与 content-x 同任务链，勿与运营五条混线程。
