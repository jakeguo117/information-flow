# content-x-article-packaging

包装三件套（Packaging Trifecta）。封面 brief／标题／引子是**一整件产品**，不是三件散件。读者扫视路径：banner 抓眼 → title 勾住 → intro 对齐预期 → 点击进文。

**谁加载**：内容写手。X 长文底稿／母稿由写手加载 content-core → content-x 来写。X 运营不再写母稿。

**谁干什么**：写手＝选题②＋包装 brief①＋basement／母稿＋CTA 文案③；视觉＝出图；渠道运营＝落版／叠字／发帖；冷读＝内容审计。

**加载顺序**：选题② → 采访／骨架 → Jake 认可 → 包装① → 正文 → CTA③。

**来源**（机制对照，非硬 KPI）：Benjamin Chan Article https://x.com/i/article/2100174331804540928 ；镜像 https://haowenji.com/articles/x-2100174331804540928 ；帖 https://x.com/ItsMeBenChan/status/2114698558712774840 。纸面：`纸面-内容侧草案-BenjaminChan-Article复活-20261027.md`。作者宣称阅读倍率等为个案，**不当验收硬数字**。

## 触发

- Jake 已认可骨架，正文还没开写；或定稿前要补封面 brief 和卖点短句。
- 账号复活／冷启动要先定包装再写流程文时，也走本 skill。

## 输入

- 已过流程选题（或本周认可选题卡）：来源资产、中心思想一句、读者是谁。
- 方向卡或 brief 里已有：终版中心思想／主论据／开场场景（若尚未确认，先走 content-core 方向确认，不先硬写包装）。
- 可选：既有热帖／案例一句话，供「卖梦想」或「拆异议」取材。
- 不输入：运营侧引用 hook 排期、出图成品、代发授权。

## 做什么

1. **先给三个位置各标一个职责**（卖梦想或拆异议，供渠道落版参考）：
   - **卖梦想（sell the dream）**：读者想要的结果／状态，具体可感知。
   - **拆异议（answer an objection）**：读者「凭什么信」「这招真的吗」「适不适合我」里的一条。
2. **分配表**（写进产出；可参考原文例，勿照搬数字当承诺）：
   - 封面（Banner）：一句职责＋brief＋卖点短句（画面要传递的一点；5:2；禁「随便 AI 封面」）。叠不叠字不在这里定。
   - 标题（Title）：一句职责＋起草标题（具体＋勾好奇＋承诺价值；禁空泛 5 秒标题、百分比钩子）。落版由渠道运营定。下一篇起标题英中各做一套：英文一套进 X Article，不直译中文标题；中文一套进中文版，供公众号／小红书。
   - 引子（Intro／短钩）：一句职责＋起草文案（对齐点击后预期）。引子同样英中各做一套。封面文案若叠字，英文字母更长，落版时重排，不硬塞中文标题的英译。
3. **落版不在本岗**：封面／标题／引子的版式，以及封面上叠不叠字，由渠道运营定（X／小红书／公号按平台）。本岗不代落版。
4. **闸门**：封面 brief、卖点短句，或标题／引子起草任一想不清 → **停写正文**。回到选题或方向卡，不硬开写。
5. **封面 brief → 内容视觉**：本岗交 brief 和卖点短句（画幅 5:2、要传达的一点、禁忌元素）；出图／裁切归内容视觉（canvas-design + content-visual）。本岗不出图。
6. **定稿前检查表**（全部勾上才放行正文或定稿）：
   - [ ] 封面 brief 和卖点短句已写
   - [ ] 标题、引子有起草文案。下一篇起英中各一套；英文标题／引子不是中文直译
   - [ ] 标题兑现点在正文里找得到（不空头承诺）
   - [ ] 封面 brief 已交视觉；本岗无出图文件冒充交付
   - [ ] 无求赞／求转／求评话术混进引子
   - [ ] 没有代渠道运营写下「叠字／不叠字」的落版决定

## 产出

- **三件套说明**：封面是 brief＋卖点短句（非成图）；标题、引子是起草文案。落版不在这份说明里定死。
- **定稿前检查表**（上文勾选项，可贴 brief）。
- 交接：封面 brief 和卖点短句 → 内容视觉；标题／引子起草进 basement。**不代发**。落版交渠道运营。

## 验收

- 封面 brief 和卖点短句已写出。
- 包装不清时正文未开写（或已叫停）。
- 封面只有 brief、无本岗出图。
- 未代渠道运营决定落版或叠不叠字。

## 渠道侧验收建议

落版时由渠道运营看。不写入上面的硬验收，也不挡写手开写正文。

- 外人一眼能说清三者各解决什么。
- 无三者同卖一个点。
- 封面卖点与标题、引子不撞车。

## 边界／不做

- 封面执行／出图归内容视觉；本岗可写 brief，不出图。
- 不代发；发帖归 X 运营。
- 不写小红书正文／caption／卡面；不写公众号。
- 不发明 Jake 没说过／未确认的观点；不把未确认 paraphrase 当包装承诺。
- 禁靠 context 才懂的词；新概念用读者懂的话。
- 与 content-core：**敏感五类**、**禁 Journal 原话**（连续 20 字撞车）对齐——此处不复述全文，加载 content-core 为准。
- 不做运营侧 ④ 引用再分发、⑤ 沉睡号复活计划（归 X 运营／content-x-ops 邻域）。
- 不把作者宣称倍率（如「70 倍」）写进包装承诺或验收数字。

## 与邻 skill 关系

- **须先或可并行**加载 `content-core`。
- 写正文时另循 `content-x`（版式／写法）；本 skill 不代替 content-x。
- 加载顺序：选题② → 采访／骨架 → Jake 认可 → 本 skill（包装①）→ content-x 正文 → `content-x-cta-loop`（CTA③）。
- 一次只做一类，或在任务里写清顺序；可与 content-x 同任务链，勿与运营五条混线程。
